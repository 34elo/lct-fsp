# bot

Telegram-бот на aiogram 3 (long polling). Бизнес-логики нет: действия пользователя — вызовы internal API core (`/internal/tg/*`, сервисный токен), исходящие сообщения — команды `notify.telegram` из очереди `bot.telegram`.

## Что умеет

- привязка аккаунта по ссылке с сайта (`/start link_<token>`); без привязки бот отправляет на сайт;
- приглашения: просмотр, «Принять», «Отклонить» с причиной, вопрос работодателю;
- профиль, категория, кнопка короткого теста, статус поиска, настройки (вилка, форматы);
- ФСП: статус привязки и обновление результатов;
- короткий тест (экспресс-режим API теста) и регулярные задания с ответом кнопками или текстом;
- резюме файлом (сигнатура, до 10 МБ, файл не сохраняется — стримится в core).

## Ключевые файлы (`fsp_bot/`)

| Файл | Что |
|---|---|
| `main.py` | Сборка: Bot, RedisStorage для состояний, подписчик `bot.telegram`, polling |
| `handlers.py` | `/start`, меню, резюме, приглашения |
| `account.py` | ФСП, категория, статус, настройки |
| `assessment.py` | Короткий тест и задания; в core ходит коротким токеном кандидата |
| `sender.py`, `limiter.py` | Отправка с редактированием по `edit_of`, лимиты 25 сообщений/с и 1/с на чат, `RetryAfter` |
| `core_client.py` | HTTP-клиент core |
| `templates/`, `states.py` | Шаблоны сообщений, клавиатуры, FSM |

```bash
TG_BOT_TOKEN=… SERVICE_TOKEN_BOT=… uv run --package fsp-bot python -m fsp_bot.main
uv run pytest services/bot -q
```

В compose — профиль `bot`, включается только при заданном `TG_BOT_TOKEN`. Токены — только из окружения; в логах нет ПДн и текстов сообщений.
