# Бриф: ФСП Карьера, UX v2

> Прикладывается к промптам [prompt-1.md](prompt-1.md) и [prompt-2.md](prompt-2.md). Решения по UX — [docs/ux/ux-spec.md](../../ux/ux-spec.md). Поля данных взяты из реального API (`docs/openapi.json`); то, чего в API пока нет, помечено **«нет в API»**.

## 1. Продукт

ФСП Карьера — платформа найма в ИТ Федерации спортивного программирования с обратной механикой.

- **Кандидат:** выбирает направление и грейд, проходит тест (у каждого свои задания, шкала общая) и получает **подтверждённую категорию** — например, «Backend · Junior». Достижения соревнований ФСП поднимают его внутри категории.
- **Работодатель:** описывает, кого ищет, видит подходящие категории и кандидатов с объяснением и **сам выходит на контакт**: сначала «интерес» с вилкой зарплаты, затем приглашение (можно с коротким заданием).
- **Контакты** кандидата открываются только после того, как он принял приглашение.

## 2. Стиль

**Главное правило: показываем, а не объясняем.** Экран понятен по данным, подписям и состоянию.

- **Запрещено:**
  - подзаголовки «Здесь вы можете…», «Мы собрали для вас…», «Так вас видят компании»;
  - описания под заголовками;
  - восклицания и эмодзи;
  - маркетинг внутри кабинета.
- **Одна главная кнопка на экран.** Остальное — вторичные кнопки и ссылки.
- **Порядок на экране:** статус → действие → детали по клику (вкладки, раскрытие, боковая панель).
- **Цифры и факты вместо прилагательных:** «Junior · подтверждён 07.10», «3 компании · 140–220 тыс. ₽».
- **Текст — только у решения:** одна строка у кнопки. Остальное — подсказка по «?».
- **Пустое состояние:** одна фраза и одна кнопка.
- **Обращение и тон:** кандидату «ты», работодателю «вы». Тон спокойный, профессиональный.
- **Подтверждено и заявлено** везде различаются одним приёмом: сплошная и пунктирная обводка. Доверие к навыку — точки ○○○○…●●●● (компонент TrustDots).

## 3. Визуальная база

- **Только существующие компоненты и токены** (H1, H2, DS1, DS2). Если нужен новый компонент — помечаешь его «новый».
- **Шрифты:** Onest — текст; JetBrains Mono — заголовки, числа, метки.
- **Цвета:** фирменный синий ФСП. Красный `--signal` — не больше одного раза на экран.
- **Тема:** светлая основная. Тёмная — карточка кандидата, вау-блоки, переключатель.
- **Размеры:**
  - каждый экран в 1440 и 375 px;
  - кандидат — mobile-first, работодатель — desktop-first;
  - без горизонтальной прокрутки.
- **Доступность:** контраст AA, подписи у всех полей.

## 6. Экраны

Формат описания каждого экрана:
1. **Вопрос** пользователя.
2. **Что даём:** ценность экрана для пользователя.
3. **Главное действие.**
4. **Сразу видно** — по приоритету.
5. **По запросу.**
6. **Состояния.**
7. **Данные с бэка:** эндпоинт и поля.

Компоновку выбирает дизайнер.

### 6.1. Главная кандидата — `/me` · ключевой

- **Вопрос:** «Где я сейчас и что делать дальше?»
- **Что даём:** понимание своего места на рынке и одно понятное следующее действие, а не набор разделов.
- **Главное действие:** одно «следующее действие», меняется по ситуации: «Пройти тест» → «Привязать ФСП» → «Ответить на интерес» → «Пройти тест на Middle».
- **Сразу видно:**
  1. Статус: Backend · Junior · подтверждён 07.10 · экспресс.
  2. Сила профиля и место в категории (64, топ-30 %).
  3. Следующее действие.
  4. «Вами интересуются: 3 · 140–220 тыс.» и новые приглашения.
- **По запросу:** навыки (подтверждено / заявлено), история тестов, ФСП.
- **Состояния:**
  - **до теста:** весь экран — одна карточка «Пройди тест — без него тебя не видят работодатели» [Пройти тест];
  - **кулдаун:** дата следующей попытки и «Можно пройти Junior сейчас»;
  - **грейд не подтверждён:** метка «не подтверждён».
- **Данные:**
  - `GET /candidates/me/profile` → `claimed_vs_confirmed` (profession, declared_grade, confirmed_grade, status), `skills[]` (name, confidence, level, claimed_only, sources), `fsp` (verified, achievements[]), `publishable`;
  - `GET /assessment/history` → attempts[] (mode: express / full, result.grade, finished_at), `cooldowns[]` (next_change_at), `retries[]`;
  - `GET /candidates/me/interests` → companies, salary_from_min, salary_to_max, items[];
  - `GET /candidates/me/offers` → новые приглашения;
  - `GET /candidates/me/navigator` → следующий шаг: test (grade, path), skill_gaps[], competitions[];
  - **есть в API:** сила профиля и место в категории — `GET /candidates/me/standing` → `strength {value, rank, top_percent, parts[]}`, `category_size`, `peers[]` для графика (E35-12a).

### 6.2. Результат теста — `/me/assessment/attempts/:id/result` · ключевой

- **Вопрос:** «Что я получил и что дальше?»
- **Что даём:** честный итог с понятной причиной и путь вперёд: подтверждение, пересдача на уровень ниже или тест на уровень выше.
- **Главное действие:** следующий шаг — «Привязать ФСП» или «Смотреть приглашения»; при неудаче — «Пройти Junior сейчас».
- **Сразу видно:**
  1. Итог: «Backend · Junior — подтверждён» или «Middle не подтверждён».
  2. Положение в полосе грейда.
  3. 2–3 ошибки по сути, например «путаешь LEFT и INNER JOIN».
  4. Пометка «экспресс».
- **По запросу:**
  - ответы по темам навыков;
  - «как устроен тест» — одна ссылка «?»;
  - «объясни ответ» для 1–2 заданий.
- **Состояния:**
  - подтверждён;
  - не подтверждён — предложение пройти тест ниже;
  - уверенно выше — приглашение на тест следующего грейда со сроком;
  - низкая уверенность — пометка;
  - требует подтверждения (честность).
- **Данные:**
  - `GET /assessment/attempts/{id}` → profession, declared_grade, mode, status, answered, low_confidence;
  - `result` (grade, theta, se, theta_by_type, integrity, needs_confirmation, by_skill, answers);
  - `invited_grade`, `invite_expires_at`;
  - `POST …/responses/{id}/explain`.

### 6.3. Подбор работодателя — `/employer` · ключевой

- **Вопрос:** «Кого я могу позвать прямо сейчас?»
- **Что даём:** от фразы «кого ищу» до подходящих проверенных людей за один шаг, без фильтров на пол-экрана.
- **Главное действие:** описать, кого ищете.
- **Сразу видно:**
  1. Строка «Backend на Python, Middle, до 220 тыс., удалёнка».
  2. Под ней карточки категорий: название, число людей, медиана ожиданий, доля с ФСП, совпадение с запросом.
  3. Активность: новые кандидаты по подпискам, ответы на интересы.
- **По запросу:** форма потребности (стек, грейд, вилка, формат), подписка на категорию.
- **Состояния:**
  - первый вход — строка и 3 примера запросов;
  - ничего не найдено — ближайшие категории.
- **Данные:**
  - `POST /needs` {text} → filters (roles, grade_min/max, skills_must, salary_max, formats…) и `categories[]` (profession, title, grade, affinity, candidates, median_salary, fsp_share);
  - `GET /subscriptions`;
  - **есть в API:** лента активности работодателя — `GET /employer/activity` (E35-12b).

### 6.4. Опрос — `/me/assessment`

- **Вопрос:** «На что я претендую?»
- **Что даём:** заявить уровень за минуту, всё предзаполнено из резюме.
- **Главное действие:** «Начать тест».
- **Сразу видно:** направление (Backend, Frontend, AI Engineer), стек чипсами, формат, вилка, грейд Junior / Middle / Senior, переключатель «экспресс, 3–5 мин».
- **По запросу:** описание грейдов по «?».
- **Состояния:** предзаполнено — пометка у полей; кулдаун — дата.
- **Данные:**
  - `GET/PUT /assessment/survey` → profession, stack[], formats[], salary_from/to, declared_grade, prefilled;
  - `GET /taxonomy/professions`.

### 6.5. Прохождение теста — `/me/assessment/attempts/:id`

- **Вопрос:** «Как решить это задание?»
- **Что даём:** спокойную обстановку без лишнего.
- **Главное действие:** «Ответить» («Не знаю» — вторичное).
- **Сразу видно:** задание (код моноширинным с отступами), таймер, номер задания.
- **По запросу:** правила по «?».
- **Состояния:** пять видов заданий:
  - `exact` — поле ответа;
  - `choice` — варианты;
  - `find_bug` — клик по строкам кода;
  - `order` — перетаскивание;
  - `sjt` — ранжирование вариантов.
- **Данные:**
  - `GET …/next` → seq, kind, stem, options[], steps[], time_limit_s, done;
  - `POST …/answers`.

### 6.6. Приглашения кандидата — `/me/offers`

- **Вопрос:** «Кто зовёт и на каких условиях?»
- **Что даём:** условия и причину выбора до разговора; контроль, кому открыться.
- **Главное действие:** «Открыть интерес» или «Принять».
- **Сразу видно:**
  - вкладки «Интересы · Приглашения · Отклики»;
  - в карточке: компания и надёжность, вилка (до НДФЛ или на руки), «почему ты» (3 факта), срок, задание (если есть).
- **По запросу:** чат, задание, отзыв доступа к контактам.
- **Состояния:** пусто — «Пока никто не пригласил» [Смотреть вакансии]; истёк; отклонён.
- **Данные:**
  - `GET /candidates/me/interests`, `/candidates/me/offers`, `/candidates/me/applications`;
  - карточка `OfferForCandidate`: status, company (name, verified, reliability: response_rate, avg_response_hours), salary_from/to, salary_basis, why_you (factors[].text, unconfirmed[]), task (title, minutes, deadline_at), message, expires_at;
  - действия: `/interests/{id}/open|decline`, `/offers/{id}/accept|decline`, `/offers/{id}/messages`, `/offers/{id}/contacts/revoke`.

### 6.7. Профиль кандидата — `/me/profile`

- **Вопрос:** «Что у меня подтверждено?»
- **Что даём:** видно, на чём держится каждый навык, и как его усилить.
- **Главное действие:** «Добавить доказательство» (ФСП, резюме).
- **Сразу видно:** вкладки «Навыки · ФСП · Резюме · Граф»; навыки с точками доверия, подтверждённые отдельно от заявленных.
- **По запросу:** доказательства навыка; граф доказательств.
- **Данные:**
  - `GET /candidates/me/profile` → skills[], experience[];
  - `GET /candidates/me/fsp` → achievements[] (title, level, place, of, year, team_role), ranks[];
  - `GET /candidates/me/graph`;
  - `GET /candidates/me/skills/{id}/evidence`.

### 6.8. Настройки — меню аватара

- **Вопрос:** «Что видят компании?»
- **Что даём:** контроль приватности.
- **Сразу видно:** переключатели: ФИО (по умолчанию выкл.), опыт и компании, ФСП, регион; согласия; уведомления в Telegram.
- **Данные:**
  - `PATCH /candidates/me/visibility` (companies, education, teams…);
  - `GET/PUT /me/consents`;
  - `POST /me/telegram/link`;
  - флаг ФИО — задача E36-4.

### 6.9. Категория — `/employer/categories/:profession/:grade`

- **Вопрос:** «Кто лучший в категории?»
- **Что даём:** сравнение проверенных людей с причинами, а не список резюме.
- **Главное действие:** «Интерес» или «В шорт-лист».
- **Сразу видно:** карточки по рангу:
  - грейд и место в полосе;
  - топ-навыки с доверием;
  - достижения ФСП;
  - вилка ожиданий;
  - 3 факта «почему»;
  - «интересовался вами»;
  - неподтверждённые — ниже, с меткой.
- **По запросу:** фильтры (стек, ФСП, формат, только подтверждённые).
- **Данные:**
  - `GET /categories/{profession}/{grade}/candidates?need_id=` → `CandidateCard`: pseudonym, grade, grade_preliminary, top_skills[], fsp_highlights[] (title, level, place, of, year), salary_min, formats, city, match (score, explanation[]), strength (value, rank, top), is_shortlisted, interested_you;
  - `POST/DELETE /needs/{id}/shortlist/{pseudo_id}`.

### 6.10. Карточка кандидата — `/employer/candidates/:id`

- **Вопрос:** «Звать ли этого человека?»
- **Что даём:** доказательства вместо резюме.
- **Главное действие:** «Интерес» или «Пригласить».
- **Сразу видно:** грейд и сила, подтверждённые навыки с источниками, ФСП, опыт и компании (по приватности), «заявлено vs подтверждено».
- **По запросу:** граф доказательств, история тестов.
- **Данные:** `GET /candidates/{pseudo_id}/card` → поля `CandidateCard` + skills[], grade_info, experience[], offers_from_you, claimed_vs_confirmed.

### 6.11. Модалка интереса или приглашения

- **Вопрос:** «Чем зацепить кандидата?»
- **Что даём:** шанс ответа ещё до отправки.
- **Главное действие:** «Отправить».
- **Сразу видно:**
  - вилка (обязательна, до НДФЛ / на руки);
  - сообщение до 300 символов;
  - задание (по желанию);
  - прогноз: «38 % → поднимите верх до 240 тыс. → 61 %»;
  - средний срок ответа.
- **Данные:**
  - `POST /offers/salary-hint` → p_accept, suggested_salary_to, suggested_p_accept, category_median, below_candidate_min, avg_response_hours, range_too_wide;
  - отправка: `POST /interests`, `POST /offers`;
  - задания компании: `GET /employer/tasks`.

### 6.12. Шорт-лист — `/employer/shortlist`

- **Вопрос:** «Кого довести до контакта?»
- **Главное действие:** «Пригласить».
- **Сразу видно:** отмеченные кандидаты и статус интереса.
- **Данные:** `GET /needs/{id}/categories` → shortlist[] + карточки.

### 6.13. Приглашения работодателя — `/employer/offers`

- **Вопрос:** «Что с моими контактами?»
- **Главное действие:** «Ответить».
- **Сразу видно:** воронка «интерес → открыл → приглашение → принято»; отклики на вакансии.
- **Данные:** `GET /offers` → `OfferForCompany` (status, candidate, salary, interest_opened_at, task, contacts), `/offers/{id}/messages`.

### 6.14. Лендинг — `/`

- **Вопрос:** «Что это и куда нажать?»
- **Главные действия:** «Пройти тест», «Найти специалиста», «Демо для жюри».
- **Пять блоков:**
  1. Суть одной фразой.
  2. Три шага: опрос и тест → категория → работодатель приходит с вилкой.
  3. Почему тест честный: «два мира», общая шкала.
  4. ФСП.
  5. Подвал: Условия, Политика ПДн, контакт.
- **Данные:** статика.

## 8. Как работать с Claude Design и передавать результат

1. **Где:** Claude Design на claude.ai (раздел Design), проект типа «Design».
2. **Дизайн-система:**
   - лучший вариант — подключить нашу как проект дизайн-системы, тогда он строит экраны из настоящих компонентов. Если доступна команда `/design-sync`, её можно запустить в Claude Code в этом репозитории: она заливает `packages/ui` в проект дизайн-системы;
   - иначе прикладываем PNG токенов и каталога (H1, H2, DS1, DS2) и `docs/design/brand.md`.
3. **Что приложить к первому сообщению:**
   - этот бриф;
   - `docs/design/brand.md`;
   - PNG `35_H1_Tokens`, `36_H2_Catalog`, `01_Main`, `02_DS2`;
   - эталоны `15_M3_Growth`, `05_B_Candidate`, `04_A_Search`;
   - логотипы из `packages/ui` / `apps/web/public`.
4. **Этапы:**
   1. [prompt-1.md](prompt-1.md) — 3 ключевых экрана, по 2–3 варианта.
   2. Выбираем варианты.
   3. [prompt-2.md](prompt-2.md) — остальные экраны.
5. **Передача в репозиторий:**
   - просим экспорт **«пакетом для разработчиков»** в структуре `screens/png`, `screens/html`, `tokens`, `docs/SCREENS.md`;
