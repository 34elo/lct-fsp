Смысл экранов (что даём пользователю, данные с бэка, состояния) — [brief.md §6](../claude-design/brief.md#6-экраны) и [ux-spec.md](../../ux/ux-spec.md).

## Что здесь лежит

| Путь | Что это | Как использовать |
|---|---|---|
| `screens/*.html` | 127 экранов: каждый — самостоятельная статичная страница | Открыть в браузере (нужен интернет для шрифтов Google Fonts). Это **эталон вида**: структура, отступы, размеры, порядок блоков, тексты |
| `fsp2.css` | Токены (`:root`) и все классы макетов | Источник токенов и примитивов для `@fsp/ui` (E38-0). Не подключать в приложение как есть — переносить в токены и компоненты |
| `screens.json` | Список экранов: файл, название, ширина, высота | Для скриптов, например снимков PNG |
| `logo.svg` | Логотип из макетов | Знак ФСП в шапке |
| `source/*.dc.html` | Исходники артбордов Claude Design | Только для справки, напрямую не запускаются |
| `screens/v2_components.html` | Доска новых компонентов | Список того, что добавить в `@fsp/ui` |

**Имена файлов:** `v2_<экран>__<состояние>_<ширина>.html`. Состояния: `main` — основное; `empty`, `loading`, `error`; плюс особые для экрана (`before`/`after`, `cooldown`, виды заданий, вкладки).

**Данные в макетах** — демо из брифа (Аня, Дмитрий, Ольга, «Северный код»…). В приложении блоки заполняются реальными полями API, список полей — в брифе §6 для каждого экрана.

## Общие элементы

- **Шапка** (десктоп) — `.hd`: знак ФСП, меню из 4 пунктов (`.nv`, активный — подчёркивание), счётчик у «Приглашений» (`.ct`), аватар (`.av`) с меню. **Мобильный** — компактная шапка `.mh` + нижняя панель `.tb` на 4 пункта.
- **Сетка** — контейнер 1280 px (`.wrap`), 12 колонок (`.g`), на десктопе 2–3 колонки.
- **Типографика** — заголовки и числа JetBrains Mono (`.h1` 26 px, `.h2` 16 px, `.num`, `.lbl`), текст Onest 14 px.
- **Состояния** — пустое `.emp` (фраза + одна кнопка), ошибка `.errc` (текст, код, «Повторить»), загрузка — скелетоны `.skl`.
- **Подтверждено / заявлено** — сплошная и пунктирная обводка (`.sk` / `.sk.d`, `.sb` / `.sb.d`), точки доверия `.dts`.

## Правила для реализации

1. **Вид — как в макете,** данные — из API (бриф §6). Ничего не добавлять сверх макета и брифа.
2. **Токены** берутся из `fsp2.css :root` в токены `@fsp/ui`. Цвета в разметке хексами не пишем.
3. **Тексты** — как в макете. Кандидату «ты», работодателю «вы». Поясняющих абзацев нет.
4. **Проверка** — экран рядом с макетом в 1440 и 375 px (E38-16). Расхождения — в отчёт задачи.
