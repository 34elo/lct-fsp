# Инструкция для агента: как верстать по макету

Источник правды по виду: `screens/png/*.png`. Источник правды по размерам и цветам: `screens/html/*.html` и `tokens/`.

## Порядок работы над экраном

1. Найдите экран в `docs/SCREENS.md`, прочитайте описание и адаптив.
2. Откройте PNG и соответствующий HTML из `screens/html`.
3. Соберите экран из компонентов `components/fsp-ui.tsx` и базовых компонентов shadcn/ui. Новый компонент делайте, только если нужного нет.
4. Цвета, шрифты, радиусы берите из токенов (`bg-brand`, `text-muted`, `font-mono`, переменные `--*`). Не вписывайте hex в разметку, если для него есть токен.
5. Реализуйте поведение из `docs/BEHAVIOR.md`.
6. Проверьте правила из `docs/DESIGN_RULES.md`: контраст, цели касания 44 px, `aria-label`, статусы с иконкой и словом.
7. Сравните результат с PNG на ширинах 1440, 1024 и 390.

## Нельзя

- Менять цвета, шрифты и скругления бренда.
- Использовать красный (`--signal`) чаще одного раза на экран: он только для знака, метки «новый», текущего шага и критичного внимания.
- Показывать смысл только цветом.
- Придумывать данные вместо `docs/DATA.md` без пометки.
- Раскрывать имя и контакты кандидата до того, как он принял оффер.
- Принимать оффер без зарплатной вилки.

## Соглашения

- Язык интерфейса: русский. Числа в формате `200 000 ₽` с неразрывным пробелом, вилка в моноширинном шрифте.
- Компоненты в `src/components/fsp/`, экраны в `src/app/…` по маршрутам из `SCREENS.md`.
- Тёмная тема переключается классом `.dark` на корне. Тёмным сделан экран кандидата для работодателя (B), граф (G1) и hero лендинга.
- `*.dc.html` из `source/` не парсить и не запускать: это формат дизайн-инструмента.
