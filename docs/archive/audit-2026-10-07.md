## Проблемы по областям

### A. Сдача и репозиторий
1. Репозиторий приватный; `main` — первый коммит; ветка по умолчанию — `main`.
2. Нет `LICENSE` (у репозитория на GitHub лицензия не указана).
3. `README.md` устарел: «Проектирование завершено, код не начат», схема с GPU RX 5700 XT — противоречит требованию «без GPU».
4. В git лежит артефакт сборки `apps/web/tsconfig.tsbuildinfo`.
5. Стенд не развёрнут (E32-8 ⏳, P2 «ждут gateway», P3 — токен бота и секреты на сервере ⏳). ТЗ: «ссылка на стенд крайне желательна».
6. Видео демо и репетиции не сделаны (E34-5, E34-6 ⏳).

### B. Демо-конфигурация
1. `ML_FAKE=true` в `.env.example` и в `gen-demo-env.sh` → резюме разбирается заглушкой `fake.parsed_resume()` (`services/ml/fsp_ml/handlers.py:38`). Правиловый разбор без LLM (E30-4) уже есть, но демо им не пользуется.
2. При `ML_FAKE=false` и `LLM_ENABLED=true` разбор текстового запроса работодателя отвечает `503 ml_unavailable` (`services/ml/fsp_ml/main.py:63`): серверного LLM-разбора нет (E7-6 сделан только на клиенте). Нужно, чтобы в любом профиле работал правиловый разбор.
3. `EMAIL_VERIFICATION_REQUIRED=false` по умолчанию и в демо. ТЗ требует регистрацию с подтверждением email — в демо её не видно.
4. LLM по умолчанию `qwen3-vl-4b` (китайская). Организаторы ждут российские модели; замер E32-3 в 🔍, дефолт не поменян.
5. В коде нет защиты от запуска с дефолтными секретами (`jwt_secret = "dev-only-change-me"`, `pseudo_id_secret`, `analytics_salt`): если на стенде забыть `.env`, сервис стартует с публично известным ключом.
6. В `docker-compose.yml` нет лимитов памяти — заявленные «lite ≤ 1,5 ГБ» не закреплены и не замерены на стенде.

### C. Критерии оценки: доказательства
1. **Подбор (35 %).** P@10 / nDCG против BM25 считаются (`tools/eval/runners/matching.py`), но цифр нет в `submission.md` и `pitch.md`. Пары «потребность — кандидат» синтетические; живой разметки HR нет.
2. **Тест (25 %).** В `submission.md` нет κ повторяемости (считается в `tools/eval_assessment`). «Согласие с экспертом» не замерено. Живые прогоны 15–25 человек + эксперт (E27-3, 👤) не проведены.
3. **Ядро навыков и эталонные резюме не проверены человеком** (P6, P7 ⏳; v1-задачи E2-1, E2-3, E2-5, E3-3 до сих пор 🔍) — на них опираются категории и метрики разбора резюме.
4. Все отчёты (`reports/`) в `.gitignore` — в репозитории нет ни одного воспроизведённого отчёта метрик.

### D. Интерфейс (подтверждено аудитом маршрутов)
1. 12 маршрутов из 65 — заглушка `Stub`: `/employer/market` (первый пункт меню работодателя), `/me/growth`, `/me/settings`, `/me/badge`, `/verify/:id` (проверка Open Badge, хотя E18-9 ✅), `/athlete/:id` (публичная карточка, хотя E15-1 ✅), `/auth/fsp/callback`, `/employer/candidates/:id/graph`, `/employer/candidates/:id/interview`, `/federation/matrix`, `/federation/demo`, `/admin/health`.
2. Всё остальное из прогона 07.10 — в эпике E35 (меню 4 + 4, главный путь, тексты, лендинг, баги).
3. Фронт собирается в **один JS-файл на 1 МБ** (ленивая загрузка только у 5 экранов). Для лендинга с целью Lighthouse ≥ 90 (E35-5) это помеха.
4. 65 экранов 🔍 никто не смотрел на 375 px и в тёмной теме.

### E. Тесты, CI, скорость разработки
1. Прогон `services/core` — **27 минут** на Windows (около 10 на CI). Каждая проверка агента стоит полчаса; самые медленные — миграции (24 с, 14 с, 10 с на тест).
2. Нет автоматического e2e демо-сценария в порядке ТЗ (E29-3, E14-6 ⏳) — главный путь проверяется только юнит-тестами.
3. На Windows падают 3 теста по среде (PDF — нужен GTK для WeasyPrint; майнинг мутаций — пути; шаблон сервиса), а сбор `services/ml` требует `PYTHONUTF8=1`. Агенты каждый раз тратят время, разбирая «известные» падения.
4. 1549 предупреждений в прогоне core (в том числе `SAWarning` от `analytics_events` после фикса autoincrement) — шум скрывает настоящие проблемы.
