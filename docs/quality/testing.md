# Тесты и проверки качества кода

## Команды

```bash
make lint              # ruff (lint + format), import-linter, ссылки в Markdown, eslint и typecheck фронта
make test              # pytest всех Python-пакетов + vitest фронта
make test-integration  # outbox → RabbitMQ → inbox на временных контейнерах
make e2e               # Playwright на стенде с демо-данными (make up && make seed)
make families-check    # банк заданий: 1000 сидов на семейство
make cards-check       # схема карточек навыков
make deadcode          # knip (фронт) и vulture (Python)
```

На Windows Python-тесты запускайте с `PYTHONUTF8=1`. Тест PDF-профиля требует системных библиотек WeasyPrint (есть в Docker-образе, в CI проверяется отдельным смоуком).

## Что покрыто

| Слой | Инструмент | Что проверяется |
|---|---|---|
| Формулы | pytest | Rasch, EAP, калибровка, SPRT, честность, доверие, сила профиля, affinity, скоринг подбора, `p_accept`, командные сигналы, uplift — на числовых примерах из документации |
| Эндпоинты | pytest + TestClient на SQLite из миграций | Права: чужой ресурс → 404, роль → 403; валидация; лимиты; идемпотентность офферов |
| Обработчики событий | pytest | Повторная доставка не меняет результат (inbox), сверка версий |
| Контракты | pytest | Схемы событий и команд, совместимость полей |
| Миграции | pytest | Цепочка Alembic поднимается с нуля |
| Банк заданий | `families-check` | Ключ вычисляется, ручки в границах, детерминизм, покрытие профессий |
| Интеграция | `make test-integration` | Outbox → RabbitMQ → inbox, SSE через UI-шину |
| Фронт | vitest + Testing Library | Модели разделов и экраны с замоканным API, контраст токенов |
| Сквозные сценарии | Playwright, `desktop` и `mobile-375` | Регистрация → тест, подбор работодателя, демо-сценарий, реестр ФСП, доступ HR, лендинг |

Итого около 1800 Python-тестов и 700 тестов фронта.

## CI

На каждый pull request (`.github/workflows/ci.yml`): ruff, import-linter, ссылки документации, сверка `docs/openapi.json` с кодом, pytest; сборка образа core и смоук PDF; `families-check` и `cards-check`; lint, typecheck, тесты и сборка фронта.

## Правила

- Формула — юнит-тест на пример из документации.
- Эндпоинт — тест прав «чужой ресурс → 404».
- Обработчик события — тест повторной доставки.
- Фронт — данные только через сгенерированный клиент, экран проверяется на 375 px и в тёмной теме.
