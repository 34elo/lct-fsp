# Дорожная карта

Что спроектировано, но не вошло в MVP, и какой критерий оценки это усиливает. Всё ниже опирается на уже готовые контракты и данные: ничего не требует переписывать ядро.

## Подбор (критерий 1)

| Фича | Что даст | На что опирается |
|---|---|---|
| **Найм команды** | Работодатель собирает команду из нескольких ролей одним запросом: потребность «backend + frontend + QA» → по категории на роль → совместимость кандидатов (общие соревнования ФСП, командные сигналы) → одно командное приглашение | Командные приглашения для команд ФСП (`team_offer_id`), командные сигналы L/T/R/G, потребности |
| **Обучение на реакциях работодателей** | Ранжирование, обученное на реальных исходах: открыл → пригласил → принял → нанят. Learning-to-rank поверх текущих признаков, затем последовательная модель «следующий кандидат» | Таблицы `impressions` (позиция, признаки) и `rec_feedback` пишутся с первого дня |
| **Кластеры специальностей и «карта рынка»** | Работодатель видит рынок: сколько людей в каждой категории, медианы ожиданий, дефицитные навыки, где конкуренция за кандидатов; кандидат — куда расти | Эмбеддинги профилей и вакансий, агрегаты по категориям, кластеризация навыков (уже предлагает новые профессии) |
| **LLM-обоснования топ-5** | Короткое человеческое резюме «почему этот кандидат» поверх формульных объяснений, со ссылками на доказательства | Команда `ml.matches.explain` в контрактах, объяснения со `evidence_ids` |
| **Интеграция с ATS** | Вакансии из ATS по ключу компании, статусы найма обратно вебхуками из outbox, экспорт кандидата только после его согласия | Outbox событий `offer.*`, `vacancy.*`; [концепция](../architecture/overview.md#концепции-за-рамками-mvp) |
| **Защита от фиктивных вакансий** | Проверка ИНН по ЕГРЮЛ и домена почты, скоринг риска вакансии, автоматическое снижение лимитов при жалобах и приглашениях без найма | Модерация, жалобы, рейтинг ответственности, лимиты |

## Тестирование и категоризация (критерий 2)

| Фича | Что даст | На что опирается |
|---|---|---|
| **ИИ-интервью** | Короткий устный или письменный разбор решения после теста: «объясни свой ответ» с оценкой рубрикой; дополнительный сигнал честности и глубины | Команды `ml.interview.generate|grade` в контрактах, «Объясни ответ» |
| **Прокторинг без слежки** | Согласованный режим для высоких грейдов: фокус вкладки, вставки из буфера, время по заданию уже собираются; дальше — повтор ключевых заданий в изменённом мире и устный вопрос | Телеметрия ответов, индекс честности |
| **Песочница с исполнением кода** | Задачи «напиши функцию» с проверкой тестами в изолированной среде | Майнинг мутаций уже исполняет подмножество Python в песочнице-интерпретаторе |
| **Расширение банка** | Полное покрытие всех 15 профессий (сейчас полное — Backend, Frontend, AI Engineer), рост уникальности вариантов у семейств с малым числом ручек | Генераторы, конструктор, генерация LLM с допуском, задачи ФСП |
| **Калибровка на живых данных** | Перекалибровка сложностей и порогов честности на реальных ответах, экспертная разметка грейдов для проверки | Онлайн-калибровка Rasch, статистика пилотов |
| **Объективный тест для дизайнеров** | Ревью макета с внесёнными дефектами (контраст, сетка, иерархия) — тот же источник ключа «порча эталона» | Дизайн-система, генератор «мира» |
| **Анализ кода GitHub** | Доказательства навыков из репозиториев кандидата («ДНК кода»), без исполнения кода | Источник доказательств `github` в модели доверия, очередь `ml.code` |

## Продукт

- **Производительность подбора**: p95 поиска при 50 пользователях — 25 с ([validation.md](../quality/validation.md#5-нагрузка-и-ресурсы)). Несколько процессов core-api, больший пул БД, предрасчёт карточек и счётчиков категорий.
- Настоящий FSP ID на Keycloak вместо мока — смена адреса и ключей клиента.
- Telegram Mini App на основе адаптивных экранов кандидата.
- Мониторинг метрик (Grafana) поверх уже собираемой аналитики.
- Доработки интерфейса: единые скругления, выравнивание в списке вакансий, полный профиль в статистике.
