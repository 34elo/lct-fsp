# ФСП Карьера — сводка проекта для жюри

Платформа найма в ИТ с обратной механикой для Федерации спортивного программирования. Работодатель не разбирает отклики: он описывает, кого ищет, видит категории проверенных кандидатов и сам приглашает конкретного человека с указанием вилки зарплаты.

**Репозиторий:** https://github.com/34elo/lct-fsp · **Стенд:** https://dashboard.fsp.patissons.tech · **Swagger:** https://dashboard.fsp.patissons.tech/api/docs

## 1. Кто мы

Команда из четырёх-пяти разработчиков, кейс «Цифровая платформа-агрегатор ИТ-вакансий с верифицированным профилем достижений участника ФСП». Репозиторий — открытый код без обфускации, история коммитов — в GitHub. Продукт выстроен вокруг двух главных критериев кейса: механики подбора (35 %) и механики тестирования с валидацией и категоризацией (25 %).

## 2. Проблема

- Работодатель вручную фильтрует сотни нерелевантных откликов силами дорогих технических специалистов.
- Кандидат откликается вслепую, не знает условий и не получает обратной связи.
- Резюме фиксирует стек и места работы, но не подтверждает умение; отбор сводится к совпадению ключевых слов.
- У ФСП есть проверяемые результаты участников, но они не превращены в карьерное преимущество.

## 3. Что мы представляем

Обратная механика: **не кандидат ищет работу, а работодатель находит человека.**

```
Кандидат:
  регистрация → опрос → сам выбирает грейд → тест → категория «профессия × грейд»
Работодатель (видит кандидата только после теста и согласия):
  потребность текстом → категории (число, медиана ожиданий, доля ФСП)
  → кандидаты с объяснением → «интересен» с вилкой → приглашение
  → кандидат принимает → контакты открыты
```

Что отличает нас от обычных площадок:

| Обычные площадки | Мы |
|---|---|
| Резюме и ключевые слова | Навыки с доказательствами и уровнем доверия ○○○○…●●●● |
| Один тест для всех, быстро утекает | Свои варианты у каждого, общая шкала сложности, измеренная на людях |
| Нейросеть придумывает вопросы | Ответ вычисляет код; LLM ответа не определяет |
| «Тест пройден на 73 %» | «Middle подтверждён, путает ссылку и копию» |
| Кандидат откликается вслепую | Работодатель приходит сам, с вилкой и объяснением, почему выбрал именно его |
| Достижения — строчка в резюме | Результаты ФСП — подтверждённое доказательство и фактор ранжирования |
| Нужна мощная видеокарта | Ядро без GPU и без LLM |

## 4. Критерий 1 — механика подбора (35 %)

**Сценарий контакта.** Потребность текстом → рекомендованные категории → кандидаты внутри категории по силе профиля → «интересен» с вилкой (кандидат видит компанию и деньги, остаётся анонимным) → приглашение с прогнозом ответа → контакты после принятия, с правом отзыва. Параллельно работают классические вакансии с откликами, подписки на категории, командные приглашения и задания в приглашениях.

**Ранжирование и объяснимость.**

```
rank     = 0.6 · соответствие потребности + 0.4 · сила профиля
сила     = 0.5·тест + 0.2·ФСП + 0.15·подтверждённые навыки + 0.1·свежесть + 0.05·полнота
```

Каждая карточка раскрывает слагаемые, навыки с источниками подтверждения, результаты ФСП с пометкой «релевантно профессии», расхождения «заявлено vs подтверждено». Кандидат без ФСП не штрафуется.

**Проверка на парах «вакансия — кандидат»** (синтетический рынок, 1000 кандидатов, 115 потребностей, 266 «приукрашивают» резюме):

| Метод | precision@10 | nDCG@10 |
|---|---|---|
| Поиск по ключевым словам | 0.118 | 0.145 |
| + фильтры грейда и зарплаты | 0.246 | 0.344 |
| **Наш подбор** | **0.275** | **0.372** |

+157 % nDCG@10 к поиску по ключевым словам; настоящая роль входит в предложенные категории для 100 % потребностей. Подробно — [matching.md](../mechanics/matching.md), [contact.md](../mechanics/contact.md).

## 5. Критерий 2 — тестирование, валидация, категоризация (25 %)

**Идея.** У каждого кандидата свои задания, но результат сопоставим.

- *Задание — код.* Генератор варианта по сиду + решатель, который вычисляет ключ. Ключ никогда не уходит на клиент; ответ проверяется пересборкой варианта на сервере.
- *Вариант живёт в «мире».* Для каждого кандидата строится вымышленная компания с графом сервисов, таблицами, метриками и командой: одно семейство выглядит как разные задачи при одинаковой сложности.
- *Сопоставимость — шкала Rasch.* Сложность принадлежит семейству и калибруется на ответах людей; якорные задания держат шкалу.
- *Грейд решает SPRT* у порога заявленного грейда: в среднем 13 заданий. Повышение — отдельным тестом по приглашению; смена грейда — не чаще раза в 90 дней; провал грейд не понижает.
- *Антисписывание без камер.* Индекс честности по скорости, уходам со вкладки, person-fit и «невозможным» совпадениям; метка «требует подтверждения».
- *Допуск заданий.* Новое задание проходит автопроверку, пилот и решение администратора; утечка и потеря различающей способности переводят его в карантин автоматически.

**Результаты валидации** (симуляция 1000 кандидатов с известным уровнем):

| Метрика | Значение | Цель |
|---|---|---|
| Точность грейда вне зоны неопределённости у порога | 94.2 % | ≥ 90 % |
| Грейд с точностью ±1 | 98.9 % | — |
| Восстановление уровня, r(θ̂, θ) | 0.869 | ≥ 0.85 |
| Различающая способность заданий, медиана r_pb | 0.406 | ≥ 0.3 |
| Максимальная экспозиция задания | 25.8 % | ≤ 30 % |
| Ответов до карантина утёкшего задания | 79.5 | ≤ 100 |
| Детектор списывания: ложные срабатывания / пойманные | 0.3 % / 80.9 % | ≤ 5 % |
| Повторяемость, κ двух попыток | 0.52 | — |

Честно: на всей выборке точность 74 % — у самого порога решение вероятностно при любом разумном тесте; там тест ставит метку «низкая уверенность». Подробно — [assessment.md](../mechanics/assessment.md), [validation.md](../quality/validation.md).

**Категоризация.** Категория = профессия × грейд, только по тесту. Профессия — набор навыков с весами; план теста берёт навыки профессии в долях по типам (фундамент, технологии, мышление, бизнес, софт, опыт). Справочник из 15 профессий растёт данными: система сама предлагает новые профессии по кластерам навыков вакансий.

## 6. ФСП

Реестр мероприятий, участников и результатов у администратора федерации; кандидат привязывает профиль одной кнопкой (поиск по email и телефону, иначе заявка администратору). Интеграция за портом `FspPort`; мок реализует OAuth 2.0 + PKCE и OIDC discovery, как будущий FSP ID на Keycloak. Результативность и релевантность дисциплины профессии дают вклад в ранжирование; уровни соревнований не ранжируются, онлайн-явки без результата почти ничего не дают. Задачи ФСП в банке не выдаются их участникам. Подробно — [fsp.md](../mechanics/fsp.md).

## 7. Архитектура

```
web (React SPA) ─┐                          ┌─► PostgreSQL + pgvector · Redis · MinIO
                 ├─► gateway (Caddy) ─► core ┤
bot (aiogram) ───┘                   api·worker·scheduler
                                          └─► RabbitMQ ◄─► ml (эмбеддинги, резюме, LLM — опционально)
                                                  ▲
                                                  └──► fsp-connector ◄─► реестр ФСП · fsp-mock
```

Модульный монолит `core` и сервисы-спутники на шине RabbitMQ; события доставляются через outbox/inbox без потерь и дублей; тест, подбор и офферы — детерминированные формулы из одного конфига. Python 3.12, FastAPI, SQLAlchemy 2, React 19, TypeScript, PostgreSQL 16 + pgvector. Подробно — [overview.md](../architecture/overview.md), [ADR](../adr/README.md).

## 8. Решения, которые мы приняли

Коротко (все 24 с обоснованием — [ADR](../adr/README.md)): категория только из теста; ключ задания только вычислением, не LLM; общая шкала вместо одинаковых заданий; классификационный тест вместо фиксированной длины; бонусный этап приглашает, а не повышает; закрыты только контакты, остальное настраивает кандидат; LLM — сменный модуль, ядро работает без неё; реестр ФСП вместо OAuth в интерфейсе; объяснимые формулы вместо обучаемых моделей.

## 9. Что можно проверить руками

1. Войти кандидатом `jury-candidate@demo.fsp.test` (пароль `demo-pass-1234`) или нажать «Демо для жюри» на лендинге.
2. Пройти опрос и экспресс-тест (3–5 минут) → получить категорию → «Привязать ФСП».
3. Войти работодателем `jury-hr@demo.fsp.test` → в строке подбора «python middle» → категория → кандидат → «Интересен» → «Пригласить».
4. Кандидатом принять приглашение → работодатель видит контакты.
5. Администратором `admin@demo.fsp.test` — допуск заданий, реестр ФСП, профессии, аналитика.

| Роль | Логин (пароль `demo-pass-1234`) | Что показывает |
