# Требования и их реализация

Сводка требований ТЗ ([case.md](case.md)) и уточнений организаторов ([qa-session.md](qa-session.md)) с указанием, где и как каждое закрыто. Статусы: ✅ сделано · 🟡 сделано частично или с оговоркой · 📄 концепция без реализации.

## Кабинет кандидата

| Требование | Статус | Как реализовано |
|---|---|---|
| Профиль вручную | ✅ | `/me/profile/edit`; `PATCH /candidates/me/profile`, предпочтения, видимость, стоп-лист |
| PDF/DOCX с автораспознаванием (ФИО, контакты, стек, грейд, роли, стаж, софт) | ✅ | `POST /candidates/me/resumes` → MinIO → команда `ml.resume.parse` → правила + Natasha + LLM по JSON-схеме → подтверждение кандидатом. Навык без цитаты из текста отбрасывается ([ml.md](../mechanics/ml.md#разбор-резюме)) |
| Стандартизированный PDF-профиль | ✅ | `GET /candidates/me/profile.pdf` (WeasyPrint) |
| Опрос → выбор грейда → тест → категория | ✅ | `/me/assessment`: IT-направление, стек, формат, вилка, грейд → попытка теста ([assessment.md](../mechanics/assessment.md)) |
| Категория и грейд, история опроса и теста | ✅ | `/me/assessment/history`, результат и разбор попытки |
| Пересдача ниже/выше с ограничением частоты | ✅ | Смена грейда раз в 90 дней, повтор того же — через 30, грейд ниже после провала — сразу; повышение — тест по приглашению бонусного этапа |
| Регулярные задания | 🟡 | `/me/tasks`: задания компании рассылаются категории раундами, ответы оценивает система или работодатель ([assessment.md](../mechanics/assessment.md#12-регулярные-задания-и-задания-работодателя)). Свежесть профиля пока считается только по дате теста |
| Приглашения с вакансией и вилкой, принять/отклонить | ✅ | `/me/offers`; также в Telegram-боте |
| Вакансии и отклик, список откликов | ✅ | `/jobs`, `POST /vacancies/{id}/apply`, `/me/offers?show=responses` |
| Приватность, согласия, связь с ФСП ID | ✅ | `/settings`: видимость полей, согласия, привязка ФСП через реестр |
| Доступ только к своим данным | ✅ | Чужой ресурс → 404 (тесты прав на каждый эндпоинт) |

## Кабинет работодателя

| Требование | Статус | Как реализовано |
|---|---|---|
| Профиль компании (описание, направление, контакты) | ✅ | `/employer/company`: информация, логотип, команда HR |
| Описание потребности | ✅ | Строка запроса текстом и/или фильтрами → `POST /needs` |
| Рекомендованные категории и кандидаты с обоснованием | ✅ | `GET /needs/{id}/categories` (affinity, число кандидатов, медиана ожиданий, доля ФСП, «почему эта категория») → `GET /categories/{p}/{g}/candidates` с объяснением силы профиля |
| Поиск по базе: специализация, грейд, категория, стек, ФСП | ✅ | `POST /search/candidates` с фильтрами; переключатель «Категории / Кандидаты» на `/employer` |
| Приглашение без вакансии с вилкой; статусы | ✅ | `POST /offers` (`vacancy_id` необязателен, тогда нужен `title`); статусы `sent → viewed → accepted/declined/expired/withdrawn → interview → hired/not_hired` |
| Вакансии и отклики | ✅ | `/employer/vacancies`, публикация, закрытие; отклики — в «Приглашениях» |
| Контакты скрыты до принятия или отклика | ✅ | Единственная точка раскрытия — переход в `accepted` (`contact_reveals`); отклик раскрывает сразу |

## Поиск и подбор

| Требование | Статус | Как реализовано |
|---|---|---|
| Выдача по категориям из теста, не по резюме | ✅ | В выдаче только кандидаты с действующим грейдом теста и согласием `profile_publication` |
| Внутри категории — по силе профиля и ФСП | ✅ | `rank = 0.6·match + 0.4·strength`, `strength = 0.5·T + 0.2·F + 0.15·S + 0.1·R + 0.05·C` ([matching.md](../mechanics/matching.md)) |
| Ранжирование по потребности с объяснимостью | ✅ | Покрытие навыков потребности по доверию + топ-3 слагаемых силы; под вакансию — скоринг с объяснениями со ссылками на доказательства |
| Уточнение без потери подборки | ✅ | Фильтры поверх потребности, шорт-лист сохраняется, состояние в URL |

## Данные и видимость

| Требование | Статус | Как реализовано |
|---|---|---|
| Вилка «от–до» в рублях в вакансии и приглашении | ✅ | Поля обязательны, `CHECK salary_to >= salary_from`; база «до НДФЛ / на руки» подписана |
| Приглашение: описание, зарплата, компания, способ связи | ✅ | `title`, `description`, вилка, `contact_method`, компания |
| Статусы у приглашений и откликов | ✅ | Автомат переходов, журнал `offer_events`, обе стороны видят статус |
| Регистрация по email с подтверждением | ✅ | Код на почту (`/auth/email/send|verify`); обязательность — флаг `EMAIL_VERIFICATION_REQUIRED` (на демо выключен) |

## Нефункциональные

| Требование | Статус | Как реализовано |
|---|---|---|
| Обычная машина, разумная память | ✅ | Профиль `lite` без LLM и GPU; ядро не требует видеокарты ([running.md](../operations/running.md)) |
| Открытый код, разделение Frontend / Backend / СУБД | ✅ | React SPA, FastAPI-сервисы, PostgreSQL ([overview.md](../architecture/overview.md)) |
| Docker и compose | ✅ | `docker-compose.yml`, профили `core`, `ml`, `bot`, `dev` |
| OpenAPI с ошибками | ✅ | [openapi.json](../openapi.json), Swagger на `/api/docs`; ошибки — Problem Details с машинным `code` |
| 152-ФЗ, согласия, роли, пароли и токены | ✅ | [security.md](../architecture/security.md) |
| Совместимость с Keycloak | 🟡 | Мок ФСП реализует OAuth 2.0 + PKCE и OIDC discovery; на демо привязка идёт через реестр ФСП |
| Десятки пользователей | ✅ | Нагрузочный сценарий Locust на 50 пользователей ([validation.md](../quality/validation.md#5-нагрузка-и-ресурсы)) |
| Мобильная версия | ✅ | Каждый экран проверяется на 375 px и в тёмной теме |
