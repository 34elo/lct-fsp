# Вопросы и ответы

Вопросы, которые команда задавала организаторам, и ответы на них. Источник ответов — [сводка сессии Q&A](qa-session.md). Внутренние решения команды — в [журнале решений](../adr/README.md).

## К организаторам

| Вопрос | Ответ | Что сделали |
|---|---|---|
| Будет ли API ФСП, в каком виде? | Нет. API, тестового клиента и описания структуры не дают намеренно: команда придумывает сама | Порт `FspPort`, мок с правдоподобным API и реестр ФСП у администратора ([fsp.md](../mechanics/fsp.md)) |
| Какие данные о достижениях есть: составы команд, роли, места, разряды, уровни? | Можно делать правдоподобно по тому, что назвали: места, разряды, дисциплины, командные результаты | DTO: соревнование, дисциплина, этап, место из N, роль в команде, разряд |
| Как подтвердить, что пользователь — этот участник? | FSP ID на Keycloak, боевых доступов не будет; имитировать вход | OAuth 2.0 + PKCE в моке; на демо — автопривязка по контактам из реестра или заявка администратору |
| Есть ли вебхуки или фильтр `since`? | Не уточнялось | Поддержаны оба: подписанный вебхук и периодическая синхронизация |
| Критерии и веса | Подбор 35 %, тест 25 %, интерфейс 10 %, питч 10 %, техника 7 %, доп. функции 7 %, документация 6 % | Приоритет — качество подбора и теста |
| Нужны ли внешние вакансии (hh и т. п.)? | Не нужны и нежелательны | Только свои вакансии и приглашения |
| Какие дисциплины приоритетны? | Все равны; можно учитывать релевантность направления профессии | Правила «дисциплина → навыки», множитель релевантности |
| Требования к согласиям (152-ФЗ) | Достаточно правового минимума | Обязательное согласие на обработку ПДн, отдельное — на показ работодателям |
| Свой сервер, внешние сервисы? | Можно; стенд жюри — 32–64 ГБ RAM, ~8 CPU, без GPU | Профили запуска без GPU |
| Можно ли показывать работодателю соревнования и места? | Да; ФИО и места работы тоже можно, закрыты только контакты | Видимость настраивает кандидат, контакты — после принятия |
| Будут ли макеты UI ФСП? | Нет; отход от гаммы ФСП не штрафуется | Своя дизайн-система в гамме ФСП ([design.md](../design.md)) |
| Шрифты | Разумные, лучше по гайду | Onest + JetBrains Mono |
| Грейд — по тесту или по достижениям? | Только по тесту категории | Грейд пишет только попытка теста |
| Как повышать грейд? | Лучше отдельным тестом | Бонусный этап → приглашение на тест следующего грейда |
| Что делать с неподтверждённым грейдом? | Лучше показывать со статусом, чем прятать; скрывать можно с обоснованием | Скрываем от работодателя до теста, обоснование — [ADR-0011](../adr/0011-visible-only-after-test.md) |
| LLM: какие можно? | Допустимы, лучше открытые и российские; облачные можно; описать использование | LLM — сменный модуль, локальный llama-server ([ml.md](../mechanics/ml.md)) |
| Задачи прошлых соревнований ФСП в тесте? | Можно как дополнительные, но без преимущества тех, кто их решал | Участнику соревнования его задачи не выдаются, DIF при допуске ([ADR-0015](../adr/0015-fsp-tasks-without-advantage.md)) |
| Задания работодателя: кто оценивает? | Эталон — система, открытый ответ — работодатель | Автопроверка или рубрика работодателя |
| Как жюри проверит тест? | Само пройдёт тест; нужен короткий путь | Экспресс-тест на 6–8 заданий и песочница жюри |
| Минимальный охват специализаций? | Двух специализаций с двумя грейдами достаточно | Полный банк — Backend, Frontend, AI Engineer; остальные в справочнике с меткой «бета» |
