# ADR-0019. ФСП: реестр у администратора и заявка вместо OAuth в интерфейсе

**Статус:** принято · **Область:** ФСП

## Контекст

Публичного API и OAuth у ФСП нет; на демо-прогоне вход «через ФСП» с кодом оказался непонятным.

## Решение

Реестр в `fsp-connector`: мероприятия, участники, результаты — вручную, списком или CSV. «Привязать ФСП» ищет участника по нормализованным email и телефону аккаунта: одно совпадение — привязка сразу, иначе заявка администратору. Реестр — источник через тот же `FspPort`, поэтому синхронизация и события `fsp.*` не меняются. OAuth + PKCE и код остаются в бэкенде для настоящего FSP ID.

## Почему

Привязка в одну кнопку, федерация ведёт данные сама; путь к FSP ID на Keycloak сохранён.

## Последствия

Без подтверждения email контакт можно указать чужой; смягчение — один участник на один аккаунт, журнал конфликтов, подтверждение email в проде.
