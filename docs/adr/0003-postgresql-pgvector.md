# ADR-0003. PostgreSQL + pgvector вместо отдельного поиска и векторной БД

**Статус:** принято · **Область:** Данные

## Контекст

Тысячи кандидатов; подбор — жёсткие фильтры + смысловая близость + скоринг; граф доказательств.

## Решение

Одна СУБД: реляционные данные, граф доказательств в типизированных таблицах с проекциями (`evidence`, `candidate_skills`), векторы в pgvector, триграммы для поиска навыков. Скоринг — в Python поверх SQL-отбора.

## Почему

Минус два сервиса, транзакционная согласованность, графовые обходы — при записи, при чтении максимум один шаг.

## Последствия

При росте до сотен тысяч профилей — отдельная read-модель поиска, наполняемая из outbox.
