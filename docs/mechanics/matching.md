# Механика подбора и категоризации

Обратная механика: работодатель описывает потребность, видит подходящие **категории** проверенных кандидатов, внутри категории — кандидатов по силе подтверждённого профиля с объяснением, и сам выходит на контакт ([contact.md](contact.md)). Публиковать вакансию для этого не обязательно.

Код — `services/core/app/matching/`, параметры — `data/scoring.yaml` (разделы `needs`, `strength`, `matching_weights`, `hard_filters`, `session_tuning`, `p_accept`, `limits`).

## 1. Категоризация

**Категория = профессия × грейд**, подтверждённый тестом ([assessment.md](assessment.md)). Справочник профессий — 15 (Backend, Frontend, Fullstack, Mobile, ML, Data Engineer, DevOps, QA, ИБ, Gamedev, Embedded, Аналитик, Продакт, Дизайнер, AI Engineer), грейды теста — Junior, Middle, Senior. Кандидат может состоять в нескольких категориях: грейд хранится на каждую профессию отдельно.

**Кто виден работодателю:**

- есть действующий грейд хотя бы по одной профессии (тест пройден, срок 365 дней не истёк);
- выдано согласие `profile_publication`;
- статус поиска не «не беспокоить», компания не в стоп-листе кандидата;
- несовершеннолетний — только с согласием родителя.

Кандидат без теста в выдаче не участвует: у него на Главной и в Статистике — подсказка пройти тест. Расхождение «заявлено в опросе / подтверждено тестом» работодатель видит в карточке ([ADR-0011](../adr/0011-visible-only-after-test.md)).

## 2. Потребность → категории

Работодатель пишет запрос текстом («middle python django, удалённо, до 250к»), заполняет фильтры или комбинирует. Текст разбирается **правилами** (справочник синонимов навыков, роли, грейды, форматы, города, деньги); если доступна LLM — она уточняет разбор, но поля формы всегда перекрывают текст. Результат — навыки «обязательно» (вес 1.0) и «желательно» (0.5), грейды и фильтры анкеты.

**Близость профессии к потребности:**

```
affinity(prof) = Σ_s min(w_need(s), w_prof(s)) / Σ_s w_need(s)
```

Показываются профессии с affinity ≥ 0.4 (не больше 6) плюс явно названные в запросе; если не прошла ни одна — лучшая с affinity > 0. Для каждой «профессия × грейд потребности» — число видимых кандидатов, медиана их ожиданий по зарплате (от 3 человек), доля участников ФСП и «почему эта категория» — навыки запроса, которые есть у профессии.

## 3. Ранжирование внутри категории

```
rank = 0.6 · match + 0.4 · strength
```

**match** — соответствие потребности: покрытие навыков запроса доверием кандидата к ним (обязательные весят вдвое больше желательных). Без навыков в запросе порядок задаёт сила профиля.

**strength** — сила подтверждённого профиля внутри категории:

```
strength = (0.5·T + 0.2·F + 0.15·S + 0.1·R + 0.05·C) · (I < 0.6 ? 0.8 : 1)
```

| Слагаемое | Вес | Смысл |
|---|---|---|
| **T** | 0.5 | Положение θ внутри полосы грейда: `clamp((θ − cut_g)/(cut_{g+1} − cut_g), 0, 1)` — «сильный Middle» выше «слабого» |
| **F** | 0.2 | Результативность в ФСП × релевантность дисциплины профессии ([fsp.md](fsp.md#сила-фсп-в-выдаче)); нет ФСП — 0, без штрафа |
| **S** | 0.15 | Среднее доверие к навыкам запроса (без запроса — к пяти сильнейшим навыкам) |
| **R** | 0.1 | Свежесть теста: `exp(−дней/180)` |
| **C** | 0.05 | Полнота анкеты |
| **I** | — | Индекс честности теста: ниже 0.6 — сила × 0.8 |

**Объяснение** в карточке: топ-3 слагаемых силы с их вкладом, навыки с уровнем доверия ○○○○…●●●● и источниками (тест, ФСП, резюме, задания), лучшие результаты ФСП с пометкой «релевантно профессии» / «другое направление», подтверждённые категории. Если кандидат скрыл ФСП — слагаемого F в объяснении нет.

**Поверх порядка:**

- множители: у кандидата ≥ 3 открытых приглашений × 0.9; показан этой компании ≥ 5 раз без действий × 0.95; «активно ищу» × 1.03; анкета обновлена за 7 дней × 1.01; кандидат сам отметил интерес к этой компании × 1.05 (и метка «вами интересовался»);
- MMR по эмбеддингам на топ-20 (λ = 0.8) — разнообразие первой страницы;
- подстройка в сессии (ниже).

## 4. Поиск по всей базе

`POST /search/candidates` — тот же пул видимых кандидатов с фильтрами: профессия, грейд (по категориям теста), «только подтверждённые» (без меток «требует подтверждения» и «низкая уверенность»), обязательные навыки с минимальным уровнем доверия, желательные навыки, ФСП (есть / дисциплины), формат, занятость, город и переезд, вилка, «активно ищу». Сортировки: соответствие, доверие, свежесть, взаимность (под вакансию). Карточка показывает запрошенное направление, если у кандидата их несколько. Страницы кешируются на 60 с по версии каталога и согласий.

## 5. Подбор под вакансию

Для опубликованной вакансии считается скоринг каждого кандидата (пересчёт по событиям вакансии и профиля, результат в `matches`).

**Жёсткие фильтры:** профиль удалён или «не беспокоить»; компания в стоп-листе; нет общего формата работы; ожидания кандидата > верх вилки × 1.1; грейд дальше чем на 1 ступень от вилки грейдов вакансии; не выполнено ≥ 2 обязательных навыков.

**Скор:**

```
base  = 0.45·skills + 0.20·semantic + 0.15·grade + 0.10·salary + 0.10·fsp
score = min(1, base · K_soft · 1.03 [«активно ищу»])
```

- `skills` — `Σ W_s · min(1, eff_conf_s / target(min_level_s)) / Σ W_s`, обязательные навыки весят ×2, смежный навык засчитывается с коэффициентом связи;
- `semantic` — `clip((cos(вакансия, кандидат) − 0.30)/0.55, 0, 1)` по эмбеддингам;
- `grade` — 1 внутри вилки, 0.5 на соседней ступени;
- `salary` — линейно от 1 (ожидания ≤ середины вилки) до 0 (= верху);
- `fsp` — сила подтверждения навыков вакансии на соревнованиях ФСП;
- `K_soft = 1 + min(β, Σ α_k·s_k)` — командные сигналы (лидерство, командная работа, результативность, рост) из фактов ФСП и репозиториев; только повышают скор, потолок β ≤ 0.12 ([skills.md](skills.md#командные-сигналы)).

Каждый пункт объяснения о кандидате ссылается на доказательства; пункт без доказательства не показывается. Сортировка «взаимность» умножает скор на вероятность принятия `p_accept`.

## 6. Подстройка выдачи в сессии

Реакции работодателя (открыл карточку, задержался, шорт-лист, приглашение, «не подходит») после 3 сигналов:

1. сдвигают вектор запроса по Роккио: `q' = norm(q + 0.3·mean(emb⁺) − 0.15·mean(emb⁻))`;
2. подстраивают веса признаков онлайн-логрегрессией с L2 к стартовым весам, каждый вес в `[0.5·w₀, 1.5·w₀]`;
3. по причинам «не подходит» подсказывают фильтры.

Жёсткие фильтры не меняются — переставляются только уже подходящие кандидаты. Работодатель видит чипсы «Учли: …» и может сбросить подстройку. Все показы (`impressions` с позицией и признаками) и реакции (`rec_feedback`) логируются — это данные для будущего обучаемого ранжирования.

## 7. Помощь работодателю при приглашении

- **Вероятность принятия** `p_accept = σ(−0.5 + 4·salary_gap + 1·format_match + 1.5·stack_interest + 0.5·rating + 0.5·active)` — подсказка «низкая / средняя / высокая», в фильтрах не участвует.
- **Прогноз ответа**: «поднимите верх вилки до X ₽ → Y %» (перебор с шагом 5 % до +40 %), средний срок ответа кандидатов категории.
- **Медиана ожиданий** категории и предупреждение, если вилка слишком широкая (верх/низ > 1.6) или ниже ожиданий кандидата.
- **Похожие кандидаты**: `0.7·J + 0.3·cos⁺`, где `J = Σ min(c_a, c_b) / Σ max(c_a, c_b)` — пересечение навыков с весом доверия, `cos⁺` — косинус эмбеддингов, обрезанный снизу нулём.
- **Подписка на категорию**: новый кандидат категории (по `candidate.category.changed`) попадает в дайджест не чаще раза в час, без ПДн.

## 8. Для кандидата

- **Сила и место в категории** — та же формула, что видит работодатель; место среди участников категории, без чужих идентификаторов.
- **Навигатор** — путь к следующему грейду: пробелы по навыкам профессии, ближайшие соревнования ФСП по нужным навыкам, ссылка на тест.
- **Uplift** — какие навыки подтвердить, чтобы подходить под больше вакансий: симуляция «навык поднят до ●●●○» тем же скорингом, жадно до 3 навыков, с медианой вилок и способом подтверждения.

## 9. Ограничения и известные отличия

- Подбор под **вакансию** использует грейд анкеты, рассчитанный по сигналам профиля (стаж, ФСП, тесты), а не грейд категории теста; видимость при этом всё равно требует пройденного теста. Подбор по **категориям** и поиск используют грейд теста.
- Медиана ожиданий и счётчики не раскрываются для групп меньше 3 человек.
- Справедливость: impact ratio «без ФСП / с ФСП» при равном T на синтетике — 0.34 (цель 0.8–1.25): вес F = 0.2 даёт участникам ФСП заметное преимущество. Это сознательный выбор по ТЗ («выше те, у кого есть результаты ФСП»); вес вынесен в конфиг ([validation.md](../quality/validation.md)).
