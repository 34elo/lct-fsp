# ML и LLM

Главный принцип: **решения принимают формулы, ML и LLM только извлекают данные и формулируют текст.** Тест, грейд, доверие, сила профиля, подбор и `p_accept` считаются детерминированно по `data/scoring.yaml`. У каждой функции, где участвует LLM, есть путь без неё ([ADR-0018](../adr/0018-llm-as-replaceable-module.md)).

Сервис — `services/ml`: `ml-api` (синхронный HTTP для core), `ml-worker-llm` (очередь `ml.llm`, `prefetch=1`, приоритеты), `ml-worker-code` (очередь `ml.code`). Core в LLM напрямую не ходит.

## Модели

| Назначение | Модель | Где работает |
|---|---|---|
| Эмбеддинги профилей, вакансий, навыков | `BAAI/bge-m3` (1024) или `intfloat/multilingual-e5-small` (384, добивается нулями до 1024) | CPU, sentence-transformers; модель скачивается при первом старте в том `hfcache`. Пока не готова — детерминированные запасные векторы, `/healthz` показывает `fallback` |
| NER в резюме (ФИО, город, организации) | Natasha (navec + slovnet, ≈ 30 МБ) | CPU, без сети |
| LLM | По умолчанию Qwen3-VL-4B (`LLM_MODEL`) в `llama-server` на хосте | GPU на стенде команды; любой OpenAI-совместимый сервер, в том числе на CPU |

LLM вызывается с `response_format: json_schema`: ответ ограничен схемой и дополнительно проверяется pydantic-моделью. Промпты версионируются: `services/ml/prompts/<задача>/v<N>.j2`.

## Режимы

| Флаг | Значение |
|---|---|
| `ML_FAKE=true` | Детерминированные заглушки по контрактам — для разработки и тестов |
| `ML_FAKE=false`, `LLM_ENABLED=true` | Настоящие модели и LLM |
| `LLM_ENABLED=false` | Без LLM: правиловые ветки везде (профиль `lite`) |

## Функции

| Функция | Где | С LLM | Без LLM |
|---|---|---|---|
| Разбор резюме | `ml.resume.parse` (очередь, приоритет 9) | Извлечение по JSON-схеме + проверка цитат | Правила + Natasha + словарь графа навыков |
| Разбор запроса работодателя | `POST /v1/query/parse` | Уточнение правилового разбора, поля формы приоритетнее | Правиловый парсер в core |
| Сопоставление нового навыка | `POST /v1/skills/resolve` | Судья по типу связи | Правиловый судья, спорное — администратору |
| Черновик карточки навыка | `POST /v1/skills/card-draft` | Черновик для администратора | Администратор пишет сам |
| Черновик ключа задания | `POST /v1/families/key-draft` | Черновик, утверждает человек | Ключ задаёт автор |
| Генерация заданий | `POST /v1/families/generate`, команда `ml.families.generate` (приоритет 0) | Формы конструктора → автопроверка → `draft` → допуск человеком | Банк растёт генераторами, майнингом, конструктором |
| LLM как кандидат | `POST /v1/families/solve` | Оценка `ai_solvable` семейства | Не считается |
| «Объясни ответ» | `POST /v1/assessment/explain` | Текст по уже найденной правилами причине | Шаблон по причине |
| Эмбеддинги | `POST /v1/embeddings` | — | Модель на CPU или запасные векторы |

## Разбор резюме

```
файл (PDF/DOCX, сигнатура, ≤ 10 МБ) → текст (PyMuPDF / python-docx)
  → правила: контакты, даты, разделы, стаж
  → Natasha: ФИО, город, организации
  → LLM по JSON-схеме: опыт, образование, навыки с цитатами, софт, заявленные грейд и роли
  → проверка цитат → нормализация по графу навыков → ParsedResume
```

- **Навык без цитаты отбрасывается**: цитата должна найтись в тексте, а название навыка — в цитате или рядом с ней. Отброшенное пишется в `warnings` разбора.
- Пустой или битый ответ LLM → запасной путь по правилам, ничего не теряется.
- Результат кандидат проверяет и подтверждает: только после этого навыки становятся доказательствами `resume` (0.25–0.40), правки — `self` (0.15).
- Софт-навыки, заявленный грейд и роли сохраняются с цитатами, но **в расчёты не входят**: категорию и грейд задаёт только тест.

## LLM и тест

В выдаче заданий, проверке ответов и расчёте грейда LLM не участвует. Её роль в тесте — офлайн-автор черновиков (с допуском человеком и пилотом) и «противник»: прогон модели как кандидата даёт `ai_solvable`, по которому выбор заданий штрафует то, что легко решается нейросетью. На синтетике LLM-«кандидат», заявивший Middle или Senior, в 90–100 % случаев получает метку «требует подтверждения» ([validation.md](../quality/validation.md)).

## Приватность

- Модель по умолчанию локальная, данные не покидают сервер.
- Облачный OpenAI-совместимый провайдер подключается настройкой `LLM_BASE_URL`; это трансграничная передача ПДн по 152-ФЗ, поэтому на нашем стенде не используется.
- Тексты резюме и ответов не пишутся в логи; в промптах объяснений нет ПДн.
- Результаты команд детерминированы по `message_id`: повторная доставка даёт дубликат, который inbox получателя отбрасывает.
