# Граф навыков и доверие

Человек описывается не списком ключевых слов, а **графом доказательств**: какие факты подтверждают какие навыки и насколько им можно верить. Профессия — взвешенный набор навыков, категория — срез для работодателя. Новые профессии появляются данными, без кода.

Код — `services/core/app/graph/` (доказательства, доверие, пересчёт) и `services/core/app/taxonomy/` (справочник). Данные справочника — `data/taxonomy/*.yaml`, карточки навыков — `data/skills/cards/*.yaml`, правила ФСП — `data/fsp/discipline_rules.yaml`.

## Справочник

- **Навык** — slug, русское название, синонимы, тип (`fundamental`, `hard`, `thinking`, `business`, `soft`, `experience`), статус (`active`, `provisional`).
- **Связи**: «родитель» (FastAPI → Python → backend) и «смежный» с коэффициентом. По родителю доверие наследуется вверх до двух уровней: `conf(родитель) = max(conf(ребёнок) × коэффициент)`.
- **Пары «точно разные»** (Java ≠ JavaScript, C ≠ C#) проверяются до любого слияния.
- **Профессия** (`roles.yaml`) — веса навыков 0..1, например у Backend: `backend` 1.0, `sql` 0.9, `rest` 0.9, `python` 0.7…
- **Карточка навыка** — утверждения по уровням, понятия и типичные заблуждения (из них «Объясни ответ» берёт подсказки).
- **Карта пакетов** (`package_map.yaml`) — библиотеки → навыки.

`core-migrate` при каждом старте загружает справочник в БД идемпотентно; изменение повышает версию и публикует `taxonomy.updated` (ml обновляет снимок для быстрого сопоставления).

## Доказательства

Факт → навык с силой 0..1. Источники и их сила:

| Источник | Сила | Затухание | Откуда |
|---|---|---|---|
| `self` | 0.15 | нет | Кандидат добавил навык вручную |
| `resume` | 0.25 — в блоке «Навыки»; 0.30 — в опыте; 0.40 — в опыте ≥ 12 мес | нет | Подтверждённый разбор резюме; навык без цитаты из текста отброшен |
| `test` | 0.75 × доля набранного по навыку; ≤ 0.59 при низкой честности | полураспад 1.5 года, действует 12 мес | Попытка теста |
| `task` | ≤ 0.5 × балл | — | Задание в приглашении работодателя |
| `fsp` | `min(0.95, w_правила × k_уровня × k_результата × k_этапа)` | полураспад 3 года | Результат соревнования × правило «дисциплина → навыки» |

Коэффициенты ФСП: уровень (региональное 0.6, межрегиональное 0.75, всероссийское 0.9, международное 1.0), результат (1–3 место 1.0, топ-10 % 0.9, топ-25 % 0.8, топ-50 % 0.7, участие 0.55), этап (финал 1.0, отбор 0.85). Непроверенная привязка ФСП — сила × 0.5. Разряд — сигнал, а не доказательство навыка.

Новый навык (`provisional`) даёт силу не больше 0.25, пока его не подтвердят ≥ 5 кандидатов или администратор.

## Доверие к навыку

```
s_eff      = s · 0.5^(возраст / период полураспада источника)
confidence = 1 − Π_источники (1 − max s_eff внутри источника)
```

Максимум внутри источника, noisy-OR между источниками: два разных независимых подтверждения сильнее одного, а десять строк резюме — не сильнее одной.

| Уровень | confidence | Точки |
|---|---|---|
| 0 | < 0.20 | ○○○○ — только заявлено |
| 1 | 0.20–0.40 | ●○○○ |
| 2 | 0.40–0.60 | ●●○○ |
| 3 | 0.60–0.80 | ●●●○ |
| 4 | ≥ 0.80 | ●●●● |

**Лестница доверия:** самооценка ○○○○ → резюме ●○○○ → тест ●●○○…●●●○ → тест + задание или ФСП ●●●○…●●●● → ФСП с призовым местом ●●●●. Потолок теста 0.75 сознательно ниже порога уровня 4: высший уровень требует независимого подтверждения.

Навык «только заявлен» (источники только `self` и `resume`) показывается работодателю отдельно и не участвует в силе профиля как подтверждённый.

## Пересчёт профиля

Любое изменение доказательств пишет `evidence.changed` и команду `core.recompute` в outbox. Пересчёт в одной транзакции:

1. собирает `candidate_skills` из активных доказательств (доверие, уровень, источники, топ-3 доказательства) с наследованием по иерархии;
2. считает основную роль и стек профиля (покрытие профилей профессий), сигнальный грейд анкеты, командные сигналы, текст профиля и эмбеддинг (только при смене текста);
3. увеличивает `profile_version`, если агрегат изменился, и пишет `skills.profile.updated`.

Команда пропускается, если `recomputed_at ≥ requested_at`: пачка из десятков доказательств даёт 1–2 пересчёта.

## Командные сигналы

Софт-навыки не получают точек доверия из самоописания. Четыре сигнала считаются только из проверяемых фактов:

| Сигнал | Из чего |
|---|---|
| L — лидерство | Капитанство команды ФСП с результатом, мейнтейнерство репозитория |
| T — командная работа | Командные выступления, повторные напарники |
| R — результативность | Сглаженная доля успешных выступлений `(успехи + 1) / (всего + 3)` |
| G — рост | Положительный тренд результатов за несколько сезонов |

В подборе под вакансию они дают коэффициент `K_soft = 1 + min(β, Σ α_k · s_k)` с весами по грейду вакансии (у Lead вес лидерства выше) и потолком β ≤ 0.12. Отсутствие сигналов ничего не снижает. Вывода «качеств» из голоса, мимики или тона нет.

## Рост справочника

**Новые навыки.** Упоминание, которого нет в справочнике (из резюме, запроса, вакансии), проходит конвейер в ml: нормализация → синонимы и нечёткий поиск → модерация (цензура, «навык ли это») → кандидаты по эмбеддингу → судья по типу связи (правила или LLM) → решение. Сам конвейер ничего не создаёт: решение применяет core, спорное уходит в очередь администратора. Навык становится `provisional`, затем `active` по поддержке или решению администратора.

**Связи.** Ночной пересчёт по профилям (уровень ≥ 2) и вакансиям: NPMI пар навыков → рёбра «смежный», lift навыка в роли → веса профессий вне ядра. Подсказки не применяются сами — администратор видит их в «Графе навыков».

**Новые профессии.** Раз в неделю система кластеризует устойчивые наборы навыков в вакансиях и запросах работодателей: сильные пары (поддержка и NPMI), связные компоненты, поддержка кластера, отличие от существующих профессий. Предложение «новая профессия» с ядром навыков появляется у администратора; принятое становится профессией, и тест по ней начинает собираться из имеющихся заданий. Демо-экран «Новая профессия» показывает этот путь на примере AI Engineer.
