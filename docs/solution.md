# ФСП Карьера: решение (концепция v2)

> ⚠️ **Рабочая версия от 2026-10-05: принята как направление, детали уточняются по ходу работы.** Где этот файл расходится с другими документами, те описывают **текущую реализацию**, а этот — **куда идём**. `ml.md`, `matching.md` и `skills.md` правим вместе с задачами E21–E23.

## 1. Кейс за минуту

- **Что просят.** Веб-платформа найма в ИТ с **обратной механикой**: работодатель сам находит кандидата в нужной категории и приглашает его, сразу указывая вилку зарплаты.
- **Категория** — это специализация × грейд. Она определяется **не резюме**, а обязательным путём: опрос → выбор грейда → тест.
- **Тест** должен быть устойчив к утечке заданий и при этом давать сопоставимую сложность. ТЗ прямо отвергает оба простых варианта: общий банк вопросов утекает, а генерация нейросетью под каждого кандидата несравнима.
- **ФСП.** Профиль связывается с ID участника ФСП, достижения поднимают кандидата в выдаче. API ФСП не дают — данные придумываем сами. Кандидат без истории ФСП должен обрабатываться корректно.
- **Критерии оценки:** подбор 35 % · тест 25 % · UI 10 % · питч 10 % · техника 7 % · дополнительный функционал 7 % · полнота 6 %.
- **Сдача:** репозиторий, презентация, стенд (или видео), документация в doc или pdf.

Подробно — [case.md](case.md), оригинал — [tz-2026.pdf](tz-2026.pdf), ответы организаторов — [notes/qa-2026.md](notes/qa-2026.md) (учтены в ADR-025).

## 2. Решение в пяти идеях

1. **Навыки, а не профессии.** Человек описывается графом навыков шести типов: фундамент, хард, инженерное мышление, бизнес, софт, опыт. Профессия — это взвешенный набор навыков. Категория (профессия × грейд) — лишь срез для работодателя. Новая профессия (например, AI Engineer) — это новый набор весов навыков, который заводит админ: тест и категория для неё работают без нового кода. Подсказки новых профессий по кластерам вакансий — расширение.
2. **Тест — сгенерированный мир.** Каждый кандидат получает свою вымышленную компанию: сервисы, код, база данных, метрики, бизнес-модель, команда, инцидент. Вопросы — это разные взгляды на этот мир. Правильный ответ **вычисляется из мира**, потому что вся правда о нём нам известна.
3. **Сложность измеряется, а не обещается.** Сложность принадлежит семейству заданий, а не варианту. Её уточняют пилотные задания, модели Rasch и Elo, якорные задания и рейтинг ФСП. Грейд определяет классификационный тест (SPRT) у порога заявленного грейда.
4. **Доверие — это лестница.** Самооценка ○○○○ → резюме ●○○○ → тест ●●○○…●●●○ → регулярные задания и «объясни ответ» ●●●○ → ФСП ●●●●. Работодатель видит расхождения вроде «заявлено Senior, подтверждено Middle».
5. **Работодатель приходит сам.** Путь: потребность → рекомендованные категории → кандидаты с объяснением → приглашение с вилкой. Публиковать вакансию для этого не обязательно.

## 3. Тестирование

**Путь кандидата:** регистрация → опрос (IT-направление = профессия, стек) → выбор грейда → тест на 20–25 минут → категория, уровни навыков и разбор ошибок. «Отрасль» из ТЗ — это IT-направление, а не индустрия (ADR-025). Для жюри есть экспресс-режим на 3–5 минут (6–8 заданий, метка «экспресс»).

**Из чего состоит задание.** Используем методологию Evidence-Centered Design:

- **утверждение** — что человек умеет на этом уровне;
- **свидетельство** — какое действие это доказывает;
- **модель задания** — какая ситуация вызывает это действие.

Семейство заданий — это код: генератор, решатель и ручки сложности. Вариант задания получается из `seed = hash(кандидат, попытка, семейство)`.

**Три источника правильного ответа.** Других не бывает:

| Источник | Как работает | Типы навыков |
|---|---|---|
| Вычисление | Исполнение кода, формула, модель (теория очередей, стоимость, статистика) | Фундамент, хард, мышление, бизнес |
| Порча эталона | В корректный артефакт вносится дефект из каталога. Дефект ловит формальная проверка: убитый мутант, нарушенное правило графа, известная истина данных | Код, архитектура, SQL, анализ данных |
| Таблица стратегий | Эксперты один раз оценивают стратегии по классам ситуаций, затем ключ уточняется по поведению сильных кандидатов | Софт (SJT), бизнес-решения |

**Умные задания — цепочки по миру.** Пример: метрики → логи → код → архитектура → ответ заказчику. Сложность задаётся числом шагов и количеством шума.

**Откуда берутся задания.** Нейросеть для наполнения банка не обязательна:

| Источник | Что даёт |
|---|---|
| Процедурные генераторы и «Мир» (наш код) | Ядро банка: бесконечно много вариантов в рамках механик |
| Майнинг мутаций из открытого кода (MIT/Apache) | Сотни заданий «найди ошибку» с доказанным ответом: мутанта ловят тесты проекта |
| Граф навыков | Задания на знание инструментов и связей |
| Конструктор заданий | Работодатели, эксперты и админ собирают задания по форме: расчёт, найди ошибку, сценарий, порядок шагов, выбор, открытая задача с рубрикой |
| Архив задач ФСП (концепция) | Задачи со сложностью из статистики соревнований |
| LLM (если есть) | Черновики генераторов и **примерный правильный ответ** с рубрикой для заданий, где ответ нельзя вычислить |

**Допуск в банк — только через админа и пилот:**

```
draft → автопроверки → pilot (без балла) → решение админа + статистика пилота → active
                                              ↘ плохая статистика → quarantine → retired
```

- В банк может попасть любое задание, в том числе открытая задача от работодателя. На балл оно влияет только после **решения админа** и **пилота**: достаточно ответов, хорошая дискриминация, стабильная сложность вариантов, нет перекоса по группам кандидатов.
- Ключ от LLM — всегда черновик. Его утверждает админ, затем уточняет пилот: правильным считается ответ, который выбирают сильные кандидаты.
- Задание компании сначала работает только в её регулярных заданиях.
- Автокарантин срабатывает при отрицательной дискриминации, апелляциях и признаках утечки.

**Роль LLM — ускоритель, а не основа.** У каждой LLM-функции есть альтернатива без модели (флаг `LLM_ENABLED`):

| Функция | С LLM | Без LLM |
|---|---|---|
| Новые задания | Черновик генератора и примерный ответ | Конструктор, процедурные генераторы, майнинг мутаций |
| Ключ для сценариев и открытых задач | Черновик ключа и рубрики | Автор заполняет сам; затем эмпирический ключ по пилоту |
| Разбор резюме | LLM по JSON-схеме с цитатами | Правила + словарь графа + Natasha NER |
| «Объясни ответ» | Оценка свободного текста по рубрике | Выбор причины из списка (каждая привязана к заблуждению); текст видит работодатель |
| Открытые ответы в регулярных заданиях | Черновик оценки по рубрике | Работодатель отмечает пункты рубрики |
| Текст запроса работодателя | LLM-разбор | Правиловый парсер (уже есть) |
| Карточки навыков, названия профессий | Черновик | Админ вручную; название из топ-навыков кластера |

Во время теста LLM не используется. Грейд и сложность она не определяет никогда.

**Грейд:**

- заявленный грейд подтверждается, если тест уверенно выше порога;
- если уверенно выше следующего порога — проходит бонусный этап и получает **приглашение на отдельный тест** следующего грейда без ожидания кулдауна; автоповышения нет (ADR-025);
- если не прошёл — сразу предлагаем тест на грейд ниже, принудительно грейд не понижаем;
- смена грейда — не чаще раза в 90 дней, повтор того же уровня — через 30 дней, результат действует 12 месяцев.

**Вакансия → тест.** Текст вакансии разбирается на навыки, уровень и домен → строится план по типам навыков → выбираются семейства → мир перекрашивается под домен вакансии. Шкала у всех тестов общая. На демо показываем три вакансии и три разных теста.

## 4. Категории и подбор

- **Категория** = профессия × грейд, подтверждённый тестом. Одновременно можно состоять в нескольких категориях.
- **Неподтверждённый грейд не прячем** (ADR-025): кандидат, заявивший грейд в опросе, но без подтверждения, виден в категории заявленного грейда с меткой «не подтверждён», его сила × 0.5. Фильтр «только подтверждённые» включён по умолчанию.
- **Сила профиля внутри категории** складывается так: тест 50 %, ФСП 20 %, подтверждённые навыки 15 %, свежесть 10 %, полнота профиля 5 %; при метке «требует подтверждения» × 0.8. Если ФСП нет, это слагаемое равно нулю, но штрафа нет. ФСП считается по результативности и числу соревнований; уровни соревнований и дисциплины не ранжируем (ADR-025). Формулы — [assessment.md §9](architecture/assessment.md#9-ранжирование-кандидатов).
- **Выдача** сортируется по `0.6·соответствие потребности + 0.4·сила профиля`. Объяснение — топ-3 слагаемых.
- **Какое задание дать следующим:** секция плана с наибольшим дефицитом → задания, лучше всего различающие у порога грейда (`P·(1−P)`), с поправкой на решаемость ИИ → случайно из топ-3 ([assessment.md §6](architecture/assessment.md#6-ранжирование-заданий-какое-задание-дать-следующим)).
- **Приглашение** содержит описание, вилку «от–до», компанию и способ связи. Контакты кандидата открываются после принятия приглашения или после отклика самого кандидата.
- **Интерес — первый шаг контакта** (ADR-026, E33-1). До приглашения работодатель отмечает «интересен»: вилка «от–до» обязательна, сообщение до 300 символов, срок 7 дней, не больше N интересов в неделю на компанию (`scoring.yaml` `limits.interest_company_per_week`). Кандидат видит «K компаний интересуются вами, вилки …» и карточки без контактов. «Открыть» — компания получает уведомление и может отправить приглашение; «не интересно» — с причиной (вилка, формат, компания, не ищу). Анонимность кандидата сохраняется до принятия приглашения.

## 5. Антисписывание

| Слой | Что делаем |
|---|---|
| Предотвращение | У каждого свой мир и свои варианты; задания по одному; таймер на задание = p95 времени честных кандидатов; ответы не уходят на клиент |
| Обнаружение | Время ответа против модели; person-fit (решил сложное, ошибся на лёгком); уход со вкладки и вставки; совпадение ответов; мультиаккаунты |
| Проверка | «Объясни ответ»; повтор задания в новом варианте внутри регулярных заданий |
| Последствия | Метка «требует подтверждения» и потолок доверия. Без банов, без камеры, без анализа лица и голоса |

## 6. Чем отличаемся

| Обычно | У нас |
|---|---|
| Резюме и ключевые слова | Граф навыков с доказательствами и уровнем доверия |
| Один тест для всех, утекает | Свой мир у каждого, сравнимый по общей шкале |
| Нейросеть сама придумывает вопросы | Ответ вычисляется кодом, сложность измеряется на людях |
| Фиксированные профессии | Профессии появляются из данных |
| Проверяют только код | Фундамент, код, мышление, бизнес, софт, опыт |
| «Тест пройден на 73 %» | «Middle подтверждён; путает ссылку и копию» |
| Кандидат откликается вслепую | Работодатель приходит сам, с вилкой и объяснением, почему выбрали именно этого кандидата |
| Нужна мощная GPU | Ядро и весь ML без LLM работают на дешёвом VPS (≈ 1–1.5 ГБ RAM); стенд жюри (32–64 ГБ, ~8 CPU) — без GPU, российская открытая LLM на CPU |

## 6.1. Что нового мы приносим в тестирование

Отдельные кирпичи известны: адаптивные тесты, генерация заданий, SJT, мутационное тестирование. Новое — в том, как мы их соединяем и применяем к найму:

1. **Тест как сгенерированный мир.** Не набор вопросов, а процедурная компания, своя у каждого кандидата. Код, архитектура, бизнес и команда — в одном связном контексте. Есть задания-цепочки через несколько областей, и ответ всё равно вычисляется.
2. **Задание с доказанным ответом.** У каждого задания есть формальный оракул: исполнение, формальная проверка дефекта или эмпирический ключ. LLM может предложить, но не может решить.
3. **Банк обновляется через пилот.** Задания из любых источников (код, работодатели, LLM, ФСП) сначала показываются без балла и допускаются по статистике и решению админа. Банк пополняется быстрее, чем утекает.
4. **Калибровка по соревнованиям под надзором.** Сложность заданий и пороги грейдов привязаны к реальным результатам ФСП, а не к мнению авторов теста.
5. **Решаемость нейросетью — свойство задания.** Каждое семейство прогоняется нашей LLM как «кандидатом». Мы знаем, какие задания ИИ решает, и учитываем это при подозрительном поведении.
6. **Честность результата — часть результата.** Мы оцениваем не только знания, но и уверенность в том, что тест прошёл сам человек. Работодатель видит обе цифры.
7. **Профессии из данных.** Тест строится по графу навыков, а не по фиксированной роли. Новая профессия появляется без нового теста.
8. **Ошибки как диагноз.** Неверные варианты закодированы заблуждениями: кандидат получает разбор, работодатель — объяснение уровнем ниже навыка.
9. **Работодатель — соавтор теста.** Его задачи проходят ту же психометрическую проверку и только после неё влияют на оценку.

## 7. Для питча (зачитать)

> «Мы не тестируем на профессию: профессии устаревают. Мы измеряем навыки, а категория — лишь срез.»

> «Мы не генерируем вопросы, мы генерируем компании. Каждый кандидат получает свою, и мы знаем о ней всю правду.»

> «Нейросеть у нас не решает, что правильно. Правильный ответ доказывают исполнение кода, формальные проверки и поведение сильных кандидатов.»

> «Сложность мы не обещаем, а измеряем — в том числе по результатам реальных соревнований ФСП.»

> «Мы не делаем вид, что онлайн-тест нельзя обмануть. Мы строим лестницу доверия, и её вершина — соревнования ФСП.»

> «Каждое задание сначала проходит пилот: в оценку попадают только те, что действительно отличают сильных от слабых.»

> «Платформа работает и без нейросети: задания пишут алгоритмы, открытый код и сами работодатели, а качество решает статистика.»

**На демо показываем:**

- сквозной путь в порядке ТЗ;
- три вакансии → три разных теста;
- «появилась профессия AI Engineer — добавили карточки навыков, тест заработал»;
- прогон нашей LLM как кандидата: какой грейд она получила и как сработал детектор.

## 9. Порядок работ

Принцип: **сначала база, потом ядро, потом фичи.** База почти не меняется при любых решениях. Ядро — наше решение без экранов. Фичи — экраны и всё, что легко переписать. Каждая веха заканчивается работающим срезом с тестами.

| Уровень | Веха | Результат |
|---|---|---|
| **1. База** | M0 | Дизайн целиком (UI-библиотека, редизайн экранов, макеты новых), каркас тестов, email, согласия, приглашение без вакансии, отклики, `lite` и режим без LLM, OpenAPI |
| **2. Ядро** | M1 | Тест через API: опрос → попытка → грейд → категория |
| | M2 | Подбор через API: потребность → категории → кандидаты по `rank`, честность |
| | M3 | Генерация: мир с доменами, семейства по миру, конструктор, допуск через админа и пилот, мутации; валидация |
| **3. Фичи** | M4 | Экраны и промежуточная сдача: сквозной путь в UI в порядке ТЗ |
| | M5 | «Объясни ответ», регулярные задания (сайт и бот), бейджи, резюме без LLM |
| | M6 | Цепочки и конвейер LLM, документ сдачи, нагрузка, полный e2e |
| | M7 | Расширения: граф доказательств, качество, админка и дашборд ФСП, бот, команды ФСП, подстройка, навигатор, рост графа |

Технический дизайн — [assessment.md](architecture/assessment.md). Задачи — [backlog.md](process/backlog.md) («v2. Вехи и порядок», E20–E30). Очередь — [plan.md §4.2](process/plan.md#42-очередь-v2). Если дата промежуточной сдачи близко, M4 идёт сразу после M2.

## 10. Принятые решения и открытые вопросы

**Решено:**
- Keycloak — только OIDC-совместимый мок, настоящий Keycloak в дорожной карте.
- «Мир» в MVP — один домен (e-commerce) + RAG-компонент для AI Engineer.
- MVP — три профессии (Backend, Frontend, Data/ML) + AI Engineer как витрина (ADR-025).
- LLM — российская открытая модель (выбор замером, E32-3); в документации — какая, как запускается и зачем. Грейд и тест от неё не зависят.
- Каталоги дефектов и таблицы стратегий: черновики пишет LLM, проверку проходят автоматически, выборочно смотрит ML.
- Живых участников для валидации собирает PM.

**Открыто:**
- сроки промежуточной и финальной сдачи (тогда пересоберём план по дням).
