# Питч и демо: план

> Как превратить готовый продукт в сильную защиту. Задачи — эпик E34 в [backlog.md](process/backlog.md). Решение — [solution.md](solution.md), архитектура и ответы на вопросы — [system.md](architecture/system.md).

## 0. Три мысли, которые жюри должно унести

1. **«Свой тест у каждого — одна шкала у всех».** Задания не утекают, результаты сравнимы, правильный ответ доказан кодом.
2. **«Работодатель приходит сам — с вилкой и объяснением».** Встречный оффер: интерес → кандидат открыл → приглашение с задачей → контакт.
3. **«ФСП — вершина доверия».** Грейд даёт тест, ФСП поднимает в категории, а без ФСП кандидат не проигрывает.

Каждый слайд и каждая минута демо работают на одну из этих мыслей. Всё остальное убираем.

## 1. Критерии → чем доказываем

| Критерий | Вес | Доказательство на защите |
|---|---|---|
| Механика подбора | 35 % | Живой встречный оффер в демо; «почему вы» у кандидата; precision@10 и nDCG против поиска по ключевым словам |
| Тест и валидация | 25 % | «Два кандидата — два мира»; экспресс-тест жюри проходит само; светофор `make metrics`: точность грейда, повторяемость, устойчивость к утечке; «LLM сдаёт наш тест» |
| Интерфейс | 10 % | Сквозной путь без подсказок, мобильная версия кандидата, тёмная тема |
| Питч | 10 % | 3 мысли, простые слова, ответы на вопросы без пауз |
| Техника | 7 % | Схема на одном слайде, запуск на стенде без GPU, нагрузка 50 пользователей |
| Дополнительное | 7 % | Отклики, регулярные задания, бот, чат, концепция защиты от фиктивных вакансий и ATS |
| Документация | 6 % | Перечень из ТЗ, ссылка на PDF и репозиторий на последнем слайде |

## 2. Структура питча: 10 минут, 12 слайдов

| Мин | Слайд | Что говорим |
|---|---|---|
| 0:00 | 1. Проблема | Резюме не доказывает навыки, кандидат откликается вслепую, работодатель фильтрует сотни откликов |
| 0:30 | 2. Решение одной фразой | «Не резюме, а доказательства: тест присваивает категорию, работодатель приходит сам» |
| 1:00 | 3. Как мы тестируем | Своя компания у каждого кандидата, ответ вычисляет код, общая шкала |
| 1:40 | 4. Почему не утекает и сравнимо | Варианты по сиду, пилот перед допуском, калибровка, классификационный тест |
| 2:20 | 5. Встречный оффер | Схема «интерес → открыл → приглашение с задачей → контакт» |
| 3:00 | 6–7. **Демо** | §3 — 4 минуты вживую (или видео) |
| 7:00 | 8. Метрики | Светофор: точность грейда, повторяемость, утечка, +X % к поиску по ключевым словам, LLM-«кандидат» |
| 7:40 | 9. ФСП | Вершина лестницы доверия, OIDC и порт к реестру, без ФСП не проигрываешь |
| 8:10 | 10. Архитектура | Одна схема, стенд без GPU, российская LLM как сменный модуль |
| 8:40 | 11. Что дальше | FSP ID, ATS, защита от фиктивных вакансий, задачи соревнований ФСП в банке |
| 9:20 | 12. Итог | Три мысли + ссылки: стенд, репозиторий, документация |

**Правила слайдов:**
- одна мысль на слайд, не больше 15 слов текста;
- скриншоты настоящего продукта, а не макетов;
- цвета и шрифты ФСП, схемы в фирменном стиле;
- термины (Rasch, SPRT) только в подписи мелким шрифтом — на слух говорим «тест останавливается, когда уверен».

## 3. Сценарий демо: 4 минуты, в порядке ТЗ

| Время | Кто | Что делаем | Что говорим |
|---|---|---|---|
| 0:00 | Кандидат Аня | Регистрация → опрос: Backend, Python, Middle | «Грейд выбирает сам кандидат — тест подтверждает» |
| 0:30 | Аня | Тест: вопрос с кодом, сценарий в команде, расчёт; через 8 заданий «Middle подтверждён», разбор ошибок | «Тест остановился, когда стал уверен. Ошибка — это диагноз, а не минус» |
| 1:15 | Борис рядом | Тот же тест, другая компания, другие числа | «У каждого свой мир — утёкший ответ бесполезен» |
| 1:40 | Аня | «Войти через ФСП» → достижения загораются | «ФСП не меняет грейд, но поднимает внутри категории» |
| 2:00 | Работодатель | Потребность текстом → категории → Аня в топе с объяснением | «Работодатель видит, почему этот человек» |
| 2:40 | Работодатель → Аня | «Интересна» с вилкой → у Ани «3 компании интересуются, 220–260» и «почему вы» → открыла | «Условия видны до разговора, спама нет» |
| 3:10 | Работодатель → Аня | Приглашение с задачей на 10 минут → push в Telegram → «Принять» → контакты, чат | «Задача вместо скрининг-звонка, результат остаётся в профиле» |
| 3:40 | Отклик | Борис откликается на вакансию — контакты открываются компании | «Кандидат без приглашений тоже может проявить инициативу» |

**Резерв** (если спросят или останется время): три вакансии → три плана теста; «новая профессия за минуту»; Глеб с меткой «требует подтверждения».

## 4. Вау-моменты

| Момент | Как показать | Зачем |
|---|---|---|
| **Два кандидата — два мира** | Разделённый экран: одно семейство, два варианта, одна шкала | Прямой ответ на главный вопрос ТЗ про утечки |
| **Нейросеть сдаёт наш тест** | Отчёт: какой грейд получила LLM, где сработал индекс честности | Честность и неожиданность; тема, о которой спросят |
| **Встречный оффер** | Кандидат видит «3 компании интересуются» с вилками | Оригинальность выхода на контакт — главный критерий |
| **Новая профессия за минуту** | Админ добавляет AI Engineer → тест и категория работают | Гибкость модели навыков |

## 5. Продукт как «конфетка»: чек-лист качества

**Интерфейс:**
- ни одного пустого экрана: везде скелетоны, пустые и ошибочные состояния с понятным текстом;
- все экраны сценария на 375 px и 1440 px, светлая и тёмная тема;
- тексты на русском, без «undefined», «Lorem», английских ошибок и технических кодов;
- анимации со смыслом: загорание навыков ФСП, остановка теста, «вами интересуются»;
- в консоли браузера нет ошибок на пути сценария.

**Данные:**
- правдоподобные вымышленные компании и вакансии;
- выдача не пустая ни при каком фильтре сценария;
- герои с узнаваемыми историями (Аня, Борис, Вика, Глеб);
- `make demo-reset` перед каждым показом.

**Скорость:**
- ответ теста ≤ 200 мс, подборка ≤ 1 с;
- первая загрузка страницы ≤ 2 с;
- push в Telegram ≤ 3 с.

**Стабильность:**
- e2e сквозного сценария зелёный каждый день;
- сценарий работает при `LLM_ENABLED=false`.

## 7. Страховка и чек-лист перед выходом

- [ ] `make demo-reset` выполнен, герои на месте.
- [ ] Стенд открывается с другой сети, вход жюри работает.
- [ ] Telegram-бот отвечает, push доходит.
- [ ] Видео на ноутбуке **локально** (не по ссылке).
- [ ] Сценарий проходит при выключенной LLM.
- [ ] Вкладки демо открыты заранее в нужном порядке, масштаб браузера 110–125 %.
- [ ] Таймер у второго человека, сигнал «минута до конца».
- [ ] Лист ответов на вопросы (system.md, раздел «Вопросы и ответы») у отвечающего.
