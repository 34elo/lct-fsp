# Безопасность и персональные данные

## Аутентификация

- **Регистрация** по email и паролю, роль выбирается при регистрации: `candidate` или `employer`. Роль `fsp_admin` выдаётся только сидом. Подтверждение email — 6-значный код на почту (TTL 15 мин, 5 попыток, повторная отправка не чаще раза в минуту). Обязательность подтверждения перед приглашением и откликом — флаг `EMAIL_VERIFICATION_REQUIRED`.
- **Пароли** — Argon2 (`argon2-cffi`). Вход без существующего пользователя выполняет «пустую» проверку хеша, чтобы время ответа не выдавало наличие аккаунта.
- **Access-токен** — JWT HS256 на 15 минут в заголовке `Authorization: Bearer`.
- **Refresh-токен** — случайная строка, в БД хранится хеш. Cookie `rt`: `HttpOnly`, `Secure` (вне dev), `SameSite=Lax`, путь `/api/v1/auth`, 30 дней. Каждое обновление выдаёт новый токен той же «семьи»; повторное использование старого токена отзывает всю семью (защита от кражи).
- **CSRF** — эндпоинты, работающие с cookie, проверяют `Origin` по списку `ALLOWED_ORIGINS`.
- **Другие входы:** Telegram Login Widget (проверка подписи токеном бота), одноразовая magic-ссылка из бота (токен в Redis, `GETDEL`), песочница жюри (только при `DEMO_MODE`).
- **HR без почты:** владелец компании создаёт доступ HR с временным паролем; при первом входе HR обязан задать свой.

## Авторизация

- Роли: `candidate`, `employer` (участник компании: `admin` — владелец, `member` — HR), `fsp_admin`.
- Зависимость `require_roles(...)` на каждом эндпоинте; чужой ресурс отдаётся как **404**, а не 403, чтобы не раскрывать существование. На каждый эндпоинт есть тест «чужой ресурс → 404».
- Internal API (`/internal/*`) закрыт на gateway и требует сервисного токена (`Authorization: Service <token>`) — отдельного для бота, ml и core.

## Персональные данные (152-ФЗ)

**Согласия** (`consents`, история хранится):

| Тип | Обязательно | Что разрешает |
|---|---|---|
| `pd_processing` | да | Обработка ПДн, без него аккаунт не создаётся |
| `profile_publication` | нет | Показ анонимной карточки работодателям; без него кандидата нет в выдаче |
| `fsp_data` | нет | Получение данных из реестра ФСП |
| `telegram_notifications` | нет | Уведомления в Telegram |
| `public_profile` | нет | Публичный профиль и бейдж по ссылке |
| `code_analysis` | нет | Зарезервировано для анализа репозиториев |

**Хранение:**

- ФИО, контакты и ссылки кандидата шифруются в БД (Fernet, ключ `PII_KEY`): `full_name_enc`, `contacts_enc`, `links_enc`.
- Работодатель адресует кандидата по `pseudo_id = HMAC(PSEUDO_ID_SECRET, user_id)[:12]` и псевдониму; `user_id` наружу не уходит.
- Файлы (резюме, аватары, логотипы) — в MinIO; тип проверяется по сигнатуре, а не по расширению; резюме до 10 МБ.

**Что видит работодатель:** до принятия приглашения или собственного отклика кандидата — только анонимную карточку. Контакты (email, телефон, Telegram) не раскрываются никогда раньше этого момента. Остальное кандидат настраивает сам ([ADR-0017](../adr/0017-visibility-only-contacts-closed.md)):

| Поле | По умолчанию |
|---|---|
| ФИО | скрыто; открывается после приглашения от этой компании или по выбору кандидата |
| Компании в опыте | видны |
| Результаты ФСП | видны |
| Регион | виден |
| Образование | скрыто |
| Команды ФСП | видны |
| Отдельные навыки | кандидат может скрыть любой |

ФИО и компании не участвуют в признаках подбора. Пол, возраст, фото и место жительства в ранжировании не используются.

**Раскрытие контактов** происходит в единственной точке — в транзакции перехода оффера в `accepted` (или при отклике) создаётся запись `contact_reveals`. Кандидат может отозвать доступ: после отзыва компания контактов не видит.

**Несовершеннолетние:** профиль с `age_group = minor` публикуется только при согласии родителя.

**Удаление аккаунта** (`DELETE /candidates/me`) необратимо стирает ПДн, резюме, доказательства и грейды; строка кандидата остаётся обезличенным «надгробием» с псевдонимом для ссылок из офферов. Остальные модули и сервисы чистят свои данные по событию `candidate.deleted`.

**Логи и аналитика:** структурированные логи без ПДн и текстов; в аналитике пользователь — псевдоним `HMAC(id, ANALYTICS_SALT)`; ячейки отчётов меньше 5 человек скрываются.

**LLM:** по умолчанию модель локальная. Облачный провайдер подключается только настройкой `LLM_BASE_URL`; передача резюме за рубеж — трансграничная передача ПДн, поэтому на нашем стенде облако не используется. Код кандидатов никогда не исполняется.

## Защита от злоупотреблений

Лимиты в Redis (скользящее окно):

| Действие | Лимит |
|---|---|
| Вход | 10/мин с IP, 5/мин на email |
| Регистрация | 10/мин с IP |
| Код подтверждения email | 5/час |
| Загрузка резюме, аватара, логотипа | по окну на пользователя |
| Сообщения в оффере | 30/час |
| «Объясни ответ» | 30/час |
| Приглашения компании | 20 за 24 ч; кандидату — не больше 10 входящих за 24 ч |
| Интересы компании | 30 за 7 дней |
| Отклики кандидата | 20 за 24 ч |
| Вход жюри | 30 за 10 мин с IP |

Плюс `Idempotency-Key` при создании оффера, модерация компаний, жалобы кандидатов и стоп-лист компаний у кандидата.

## Секреты

Только в `.env` (в git не попадает). `make up` без `.env` генерирует `.env.demo` со случайными секретами. Сервисам в RabbitMQ и PostgreSQL выданы отдельные пользователи с минимальными правами.
