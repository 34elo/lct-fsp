# Админка ФСП: концепция

> Роль `fsp_admin`. Задача E39-29, правки владельца — [ux/feedback.md](../ux/feedback.md) раздел «Админка». Маршруты — [frontend.md §1](frontend.md#1-карта-маршрутов), эндпоинты — [api.md](api.md) (строки `/admin/*`).

## 1. Принцип: модерируется только очередь

Админ **не проверяет каждого кандидата, тест или подбор**. Тест, грейд, подбор, калибровка и сила работают сами: решения принимают формулы и пороги из `scoring_config` (AGENTS.md, правило 4 «Детерминированное ядро»). Человек нужен только там, где у платформы нет надёжного автоматического ответа. Таких мест пять, и каждое — очередь со счётчиком на главной админки.

Следствия для интерфейса:

- на главной (`/federation`) — блок «Что требует вас» со счётчиками очередей и короткий текст «Модерируется только это — остальное платформа делает автоматически»;
- очередь пуста — спокойное сообщение «Сейчас ничего не ждёт вашего решения», без тревожных цветов;
- аналитика (воронка, качество) — только для чтения, действий в ней нет.

## 2. Что делает админ

| Очередь или справочник | Страница | Что делает админ | Что происходит само | API |
|---|---|---|---|---|
| **Заявки ФСП** | `/federation/requests` | Сверяет заявку с участником реестра, принимает или отклоняет с причиной | Совпадение email или телефона с реестром привязывает кандидата сразу, без заявки (ADR-052) | `GET /admin/fsp/requests`, `POST …/{id}/accept|reject` |
| **Допуск заданий** | `/admin/families` | Допускает семейство после пилота, отправляет в карантин, снимает; утверждает ключ задания компании | Статистика пилота и пороги допуска считаются сами; «Допустить» открыто только при всех порогах; активное задание с тревожной статистикой уходит в карантин без админа ([assessment.md §7](assessment.md)) | `GET /admin/families?status=pilot`, `POST /admin/families/{id}/…` |
| **Модерация** | `/federation/moderation` | Подтверждает или отклоняет компанию; разбирает жалобы на приглашения | Лимиты приглашений и ответственность компании считаются без админа | `GET /admin/companies?status=pending`, `GET /admin/complaints?status=open` |
| **Реестр ФСП** (справочник) | `/federation/registry` | Заводит мероприятия, добавляет участников руками или CSV, ставит места | Результаты из реестра попадают в граф доказательств и силу кандидата | `/admin/fsp/events|participants|results` |
| **Профессии** (справочник) | `/admin/professions` | Добавляет профессию, правит веса навыков и карточки навыков | Категории кандидатов пересчитываются по новой версии справочника | `/admin/professions`, `/admin/skill-cards` |
| **Граф навыков** (справочник) | `/admin/skills` | Подтверждает спорные слияния (уверенность 0.6–0.9), пары «точно разные», стоп-лист, новые навыки | Уверенные решения конвейер принимает сам; каждая правка поднимает версию справочника ([skills.md](skills.md)) | `/admin/skills/*` |

Слияния навыков — тоже очередь (счётчик «Навыки на проверке»), но живут на странице графа навыков, поэтому в меню это справочник.

## 3. Главная: «Что требует вас»

`GET /admin/summary` (только `fsp_admin`, `analytics/admin_summary.py`) → `AdminSummaryOut`:

```json
{ "queues": [
    { "id": "fsp_requests", "count": 3 },
    { "id": "families", "count": 2 },
    { "id": "skills", "count": 0 },
    { "id": "companies", "count": 1 },
    { "id": "complaints", "count": 0 }
  ],
  "total": 6 }
```

| `id` | Что считаем | Откуда | Куда ведёт плитка |
|---|---|---|---|
| `fsp_requests` | Заявки на привязку в статусе `pending` | fsp-connector (`/internal/registry/requests?status=pending`) | `/federation/requests` |
| `families` | Семейства в статусе `pilot` | `assessment.service.count_families` | `/admin/families` |
| `skills` | Предложенные слияния навыков | `taxonomy.service.pending_merge_count` | `/admin/skills` |
| `companies` | Компании в статусе `pending` | `companies.service.count_by_status` | `/federation/moderation` |
| `complaints` | Жалобы в статусе `open` | `offers.service.count_complaints` | `/federation/moderation?tab=complaints` |

Правила: порядок очередей фиксирован; fsp-connector недоступен или не настроен — `count: null` (плитка «нет связи»), остальные счётчики отдаются; `total` — сумма известных счётчиков. Только числа, без ПДн. Тесты — `services/core/tests/test_admin_summary.py`.

Под счётчиками — блок «Работает само» (§4) и ссылки на «Воронку» и «Качество».

## 4. Что работает само

| Часть | Как работает | Где посмотреть | Когда вмешаться |
|---|---|---|---|
| Тест | Адаптивно подбирает задания и останавливается, когда уровень ясен (Rasch + SPRT, [assessment.md](assessment.md)) | «Качество» | Метрика теста красная на «Качестве» |
| Грейд и категория | Выставляются по результату теста, без ручной проверки | «Воронка» (шаг «категория») | Никогда вручную; чинят формулу или банк |
| Подбор | Работодатель видит категории и кандидатов с объяснением; порядок задают формулы ([matching.md](matching.md)) | «Качество» | Метрика подбора красная |
| Калибровка | Сложность заданий уточняется по ответам; тревога → карантин | «Допуск заданий», вкладка «Карантин» | Семейство в карантине — решить, вернуть или снять |
| Сила и доверие | Считаются из доказательств и результатов ФСП относительно лидера категории ([graph.md](graph.md)) | Карточка кандидата у работодателя | Никогда вручную |

## 5. Меню и страницы

Меню (`NAV.admin` в `app/routes.ts`): **Главная**, затем три группы (`ADMIN_GROUPS`):

- **Очереди** — где нужно решение: Заявки ФСП · Допуск заданий · Модерация;
- **Справочники** — что админ ведёт: Реестр ФСП · Профессии · Граф навыков;
- **Аналитика** — только чтение: Воронка (`/federation/funnel`, бывший «Дашборд ФСП») · Качество.

В группе не больше 4 пунктов (`routes.test.ts`). На десктопе — боковая панель с подписями групп, на телефоне (< 768 px) — строка разделов под шапкой с горизонтальной прокруткой, активный пункт докручивается в видимую область. Вау-экраны `/admin/demo/*` в меню не входят: они для показа жюри. Знак ФСП на десктопе показывается один раз — в боковой панели; в шапке он остаётся только на телефоне.

Автоаудит всех страниц (консоль, сеть, переполнение, обе темы, 1440 и 375) — `apps/web/e2e/b2-admin-audit.spec.ts`, отчёт — `reports/admin-audit.md`.

**У каждой страницы — подзаголовок «зачем» и ⓘ.** Шапка `AdminPageHeader` (`features/admin/PageHeader.tsx`): заголовок, рядом ⓘ с подробностями (что делаете вы, что работает само), под ним одна фраза «зачем» из словаря `WHY` (`features/admin/text.ts`) по адресу страницы. Тест проверяет, что у каждого маршрута раздела `admin` есть фраза «зачем».

## 6. Какие данные видит админ

| Где | Данные | Ограничения |
|---|---|---|
| Воронка | Агрегаты по `analytics_events` | Ячейки меньше 5 человек скрыты ([metrics.md](metrics.md)) |
| Реестр и заявки ФСП | ФИО, email, телефон участников и заявителей | Хранятся в БД fsp-connector; в логи не пишутся ([fsp.md](fsp.md)) |
| Модерация | Название и ИНН компании, текст жалобы, номер приглашения | Контакты кандидата не показываются |
| Справочники, допуск | Навыки, профессии, задания и их статистика | ПДн нет |
| Качество | Офлайн-метрики `make metrics`, живые прогоны | Только агрегаты |
