## 2. Фронт: React SPA, Next.js или два проекта

| Критерий | React + Vite SPA | Next.js (App Router) | Два проекта (лендинг + приложение) |
|---|---|---|---|
| Скорость старта и сборки | ✅ мгновенно | ⚠️ медленнее, больше концепций (RSC, server actions, кеш Next) | ⚠️ два пайплайна |
| SEO и публичные страницы | ⚠️ SEO нет, но для хакатона не нужно | ✅ | ✅ для лендинга |
| Превью ссылок (OG) для публичного профиля | ✅ решается бэкендом: `/athlete/{slug}` для ботов-краулеров отдаёт HTML с OG-тегами | ✅ из коробки | ✅ |
| Авторизация | ✅ JWT в памяти + refresh-cookie, без серверного рендера | ⚠️ надо синхронизировать cookie между сервером Next и API | ⚠️ |
| Деплой | ✅ статика за Caddy/nginx | ⚠️ нужен Node-рантайм | ⚠️ |
| Общие компоненты кандидата, работодателя и админа | ✅ один код, ленивые разделы | ✅ | ❌ дублирование или общий пакет |
| Риск на хакатоне | низкий | средний | средний |

**Решение:** **один React + Vite SPA** с ленивой загрузкой разделов по ролям (`/`, `/onboarding`, `/me/*`, `/employer/*`, `/federation/*`, `/admin/*`, `/athlete/:id`). Публичные «SEO-подобные» нужды закрываем так:
- бейдж для GitHub — SVG прямо из `core-api` (`/public/badge/{slug}.svg`);
- превью публичного профиля — `core-api` отдаёт краулерам (Telegram, VK, Slack по User-Agent) маленький HTML с OG-тегами и картинкой-карточкой, людям — SPA.

Если после хакатона понадобится настоящий SEO-лендинг, его отдельно делают на Astro, приложение не трогаем. ADR-003.

## 3. Бэкенд: Python или Go

| Критерий | Python / FastAPI | Go |
|---|---|---|
| Общий код с ML (контракты, справочник, нормализация) | ✅ один пакет `contracts` | ❌ дублирование схем, кодогенерация |
| Скорость разработки CRUD + бизнес-правил | ✅ | ⚠️ больше бойлерплейта |
| Генерация OpenAPI | ✅ из кода | ⚠️ swaggo/oapi-codegen, отдельная дисциплина |
| Производительность | достаточно: 500–2000 кандидатов, десятки RPS | избыточна для задачи |
| Найм пользователями жюри «в голове» | нейтрально | нейтрально |

**Решение:** Python везде (core, ml, bot, mock). ADR-002.

## 4. От чего сознательно отказались

| Технология | Почему нет |
|---|---|
| Kafka / NATS | Для нашего объёма RabbitMQ закрывает всё: маршрутизация, подтверждения, приоритеты, DLQ, веб-интерфейс. Kafka избыточна (журнал событий и партиции не нужны) |
| Redis Streams + Taskiq (вариант v0.1) | Заменено RabbitMQ (ADR-012): нативные приоритеты очередей для GPU, DLQ и маршрутизация событий без самописных обвязок |
| Elasticsearch / OpenSearch | На тысячах профилей PG с FTS, pg_trgm и pgvector быстрее в разработке и транзакционен с фильтрами (ADR-004) |
| Отдельная векторная БД (Qdrant, Milvus) | То же. pgvector HNSW с фильтрами в одном SQL-запросе |
| Celery | Слабая поддержка asyncio, тяжёлый |
| Kubernetes | Один сервер, Compose достаточно |
| WebSocket | Нужен только поток «сервер → клиент», SSE проще и проходит через любые прокси (ADR-009) |
| Облачные LLM | Запрещено ограничением «только локальные модели». Для разработки тоже не используем, чтобы промпты не разъехались с локальной моделью |
| Ollama на ROCm | gfx1010 не поддерживается ROCm официально. Если Ollama с Vulkan стабильно заработает на 5700 XT, можно взять её, API тот же OpenAI-совместимый |
| Telegram Mini App | Нет мобильного разработчика, кнопки бота открывают адаптивный сайт |
