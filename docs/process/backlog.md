# Бэклог (черновик для постановки задач)

> Источник задач для трекера. Роли: **B1** — бэкенд (ядро), **B2** — бэкенд (интеграции: офферы, бот, ФСП), **FE** — фронтенд, **ML**, **PM**. В команде из 4 человек задачи B2 делят B1 и FE (бот на aiogram простой).
> Приоритет: M / S / C (MoSCoW). **Д** — день хакатона, к концу которого задача должна быть готова.

> 🔀 **Два блока (2026-10-05).** Задачи распределены между блоками, добавлены этап 0 (`S0-*`) и половины `a`/`b` — раздел [«Два блока»](#два-блока-этап-0-и-разделённые-задачи) и [blocks.md](blocks.md).

> ⚠️ **Концепция v2 (2026-10-05).** Задачи v2 — раздел [«v2. Вехи и порядок»](#v2-вехи-и-порядок) и эпики E20–E31 в конце файла; технический дизайн — [assessment.md](../architecture/assessment.md). E11 заменён на E22. Очередь — [plan.md §4.2](plan.md#42-очередь-v2).

## Вехи

| Веха | К концу | Критерий |
|---|---|---|
| **M0** Каркас | Д1 | Compose поднимается на сервере, домен с TLS открывается, LLM замерена и выбрана, контракты v1 согласованы, черновик справочника |
| **M1** Кандидат | Д3 | Резюме → разбор → ФСП (мок) → профиль с доверием, категорией и грейдом на сайте |

| **M3** Подтверждение | Д7 | ДНК кода, адаптивный тест (сайт + бот), поиск текстом, карта рынка, навигатор |
| **M4** Вау и качество | Д9 | Вау-фичи по ресурсам, страница качества с метриками, полировка по брендбуку, документация |
| **M5** Фриз | Д10 | Репетиции, видео демо, питч |

**Зачем.** Сейчас интерфейс расходится с макетами. Что видно на стенде (2026-10-03):
- По умолчанию включена тёмная тема, а макеты светлые. Тёмными должны быть только экраны B и G1 и hero лендинга.
- В поиске фильтры стоят формой сверху и занимают первый экран. Выдача идёт плиткой в 2 колонки. В макете A слева колонка фильтров, справа список карточек во всю ширину.
- Псевдонимы выводятся как «Candidate #1161». Должно быть «Backend #1161», по роли.
- В строке ФСП место выводится дважды: «107 место из 107, 107 место».
- В карточке кандидата у каждого навыка повторяются «Только заявлено…» и «Указано в резюме». Получается стена текста.
- Из компонентов в `shared/ui` есть только `button.tsx`. Поля, селекты и вкладки каждая страница собирает сама. Иконок нет. Тема переключается словом «Авто».
- Тень `--shadow-card` (`0 20px 50px rgba(0,0,0,.35)`) слишком тяжёлая для светлой темы.
- Офферы и вакансии работодателя выглядят как сетка одинаковых карточек. В макете E5 офферы — канбан по статусам.

**Источник правды.**

Пакет дизайна лежит в [docs/design/pack/](../design/pack/). Галерея всех экранов — `index.html`.

| Что | Где |
|---|---|
| Как должен выглядеть экран | `pack/screens/png/NN_<ID>.png` — эталон, сверяемся с ним |
| Размеры, отступы, цвета | `pack/screens/html/<ID>.html` — статичный снимок. Переносим в компоненты, а не копируем |
| Маршрут, адаптив | [pack/docs/SCREENS.md](../design/pack/docs/SCREENS.md) |
| Бренд, доступность, «нельзя» | [pack/docs/DESIGN_RULES.md](../design/pack/docs/DESIGN_RULES.md), [pack/AGENTS.md](../design/pack/AGENTS.md) |
| Формулы интерактива | [pack/docs/BEHAVIOR.md](../design/pack/docs/BEHAVIOR.md). Формулы-заглушки из макета (превью вакансии, медиана 275 000 ₽) заменяем данными API. Если API нет — блок скрываем |
| Токены и компоненты | `pack/tokens/`, `pack/components/fsp-ui.tsx`. Поправки к ним — [brief.md §0](../design/brief.md) («Что поправить при переносе») |

Макет сделан под Tailwind 3 и React 18. У нас Tailwind 4 (`@theme`) и React 19, поэтому конфиг переносим, а не копируем.

**Правила для E19.**

1. **Коммиты** с ID задачи: `feat(web/ui): E19-3 фирменные компоненты`.
2. **Компоненты живут в `packages/ui`** (пакет `@fsp/ui`). Экраны в `apps/web` собираются только из него. Свой компонент на экране — только если он нужен одному экрану.
3. **Данные — только через orval-хуки** из `apps/web/src/api`. Данные из `pack/docs/DATA.md` — только в playground и тестах. Если на экране есть блок, а в API нет данных для него, блок не рисуем и пишем об этом в отчёте.
4. **Логику не ломаем.** Существующие тесты `apps/web` должны проходить. Тексты и `aria-label` можно менять — тогда правим и тесты.
5. **Сверка с эталоном обязательна.** Сделай скриншоты на ширинах 1440, 1024 и 390 (после E19-0 — `pnpm shot`). Открой их вместе с PNG из пакета и перечисли расхождения. До 3 итераций правок. Что осталось — в отчёт.
6. **Проверки перед коммитом:** `pnpm -r lint`, `pnpm -r typecheck`, `pnpm -r test`, `pnpm --filter fsp-web build`. Вывод через `tail`.
7. **Нельзя:** менять бренд (цвета, шрифты, радиусы), ставить красный `--signal` больше одного раза на экран, показывать смысл только цветом, раскрывать ПДн кандидата до принятия оффера. Подробно — [pack/AGENTS.md](../design/pack/AGENTS.md).

Рынок E1, граф G1–G3, рост M3, админка и качество в E19 не входят: это E7-8, E16-3, E16-7, E12-3, E13-4, E14-4. Если такие экраны сделаны раньше E19-15, финальный проход приводит их к общему виду, а если позже — их собирают из `@fsp/ui`.
