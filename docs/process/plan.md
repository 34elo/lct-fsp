# План работ

> Как движемся по дням, кто что делает днём и что агенты делают ночью. Описания задач и критерии готовности — в [backlog.md](backlog.md). Как запускать — [workflow.md §7.5](workflow.md#75-вайбкодинг-по-плану-vibe): `/vibe` в чате Claude Code.
> **Д0** — первый день разработки. Привязку к датам делаем, когда организаторы подтвердят дедлайн.

## 1. Принципы

1. **Сквозной сценарий к концу Д5 и дальше каждый вечер.** Резюме → ФСП → профиль с точками → поиск → оффер → push в Telegram → принять. Это не обсуждается.
2. **Днём люди, ночью агенты.** Днём — то, где нужен человек: железо, данные, дизайн, проверка результатов, интеграция, решения. Агенты (`/vibe`) закрывают задачи 🤖 и 🤝 из очереди (§4) на ветке `vibe`. Утром — ревью и мерж.
3. **Заглушки вместо ожидания.** `ML_FAKE=true`, мок ФСП, токены бренда вместо готового дизайна. Никто не ждёт GPU, API ФСП и макетов.
4. **Линия отсечения** (§5): если отстаём, режем снизу вверх и не трогаем ядро.

## 4. Очередь для агентов

Её читает команда `/vibe` (диспетчер). В режиме `/vibe` предусловия `P*` считаются выполненными: недостающее заменяется заглушками. **Правила таблицы:**
- **Режим:** 🤖 — агент делает полностью; 🤝 — агент делает черновик, человек проверяет днём; 👤 — только человек (в очереди для справки, агенты пропускают).
- **Зависит от:** ID задач или предусловия людей `P1…P8` (§4.1). Задача берётся, только когда все зависимости отмечены ✅.
- **Статус:** `⏳` ждёт · `✅ <хеш>` сделано · `⛔ <причина>` заблокировано · `🔍` сделано, ждёт ревью человека (для 🤝). Агенты меняют только колонку «Статус».
