# Автоаудит админки (E39-30)

Скрипт: `apps/web/e2e/b2-admin-audit.spec.ts` (Playwright, Chrome). Запуск на стенде с сидом:

```
make up-lite && make seed
cd apps/web && E2E_CHANNEL=chrome pnpm e2e e2e/b2-admin-audit.spec.ts --project=desktop
```

Сырые находки пишутся в `reports/admin-audit.json` (переменная `ADMIN_AUDIT_OUT`); тест падает только на P1.

## Метод

- Стенд: настоящий `up-lite` (Docker, gateway :28080) с сидом, вход под `admin@demo.fsp.test`. Моки API не использовались.
- 14 маршрутов: `/federation`, `/federation/{requests,moderation,registry,funnel}`, `/admin/{families,professions,skills}`, `/admin/quality`, `/admin/quality/{fairness,runs}`, `/admin/demo/{two-worlds,llm-exam,new-profession}`.
- 1440 и 375, светлая и тёмная тема (4 прогона, ~12 минут).
- Проверки на каждой странице: `console.error/warning`, `pageerror`, упавшие запросы и ответы API >= 400, пустая страница, «undefined/NaN/[object»/«Ошибка»/«Не удалось» в тексте, горизонтальная прокрутка, число `h1`, двойной знак ФСП, белые блоки в тёмной теме, ссылки с `href="#"` и кнопки без имени, нажатие безопасных кнопок и вкладок (изменяющие данные не нажимались) с проверкой, что что-то изменилось, переход по всем внутренним ссылкам со страниц админки.
- Кроме автоматики вручную просмотрены снимки 8 экранов на 1440 (светлая) и 375 (тёмная).

## Итог

Открытых P1 и P2 нет. Ошибок консоли, пятисотых, горизонтальной прокрутки, пустых и сломанных состояний, белых блоков в тёмной теме и мёртвых ссылок не найдено.

## Найдено и исправлено

| Серьёзность | Где | Что | Исправление |
|---|---|---|---|
| P2 | `/admin/quality` | В админке виден текст разработчика: «load: нет reports/load/load_stats.csv (нужен `make up`, `make seed`, `make load`)» | Текст чистится: «Не измерено — load: нет reports/load/load_stats.csv», команды убраны (`quality/text.ts`, тест) |
| P3 | все страницы админки, десктоп | Знак ФСП показан дважды: в боковой панели и в шапке (известная мелочь E39-29) | В шапке знак скрыт с `md` у админки (`AppHeader brandFromMd`), на телефоне остаётся; тест в `shell.test.tsx` |

## Не ошибки (ложные срабатывания, учтены в скрипте)

- «Открыта» на `/federation/moderation` и «Пилот» на `/admin/families` — уже выбранные фильтры без видимого эффекта при повторном нажатии.
- `POST /auth/refresh` -> 401 при очень быстрых переходах между страницами (300 мс): refresh-cookie ротируется, и прерванная навигация съедает предыдущий токен. При обычном темпе (0,8 с) воспроизвести не удалось, пользователя не затрагивает.

## Оставшиеся P3

- Гонка ротации refresh-токена при очень быстрой навигации (см. выше): стоит дать refresh-ответу переживать повтор с тем же cookie короткое окно (блок 1, `identity`); не блокирует.
- `/federation/registry`, вкладка «Мероприятия», на стенде без `seed fsp-registry` пуста: корректное пустое состояние, но данные для демо — после `make seed`.
- `/admin/quality/runs`: фильтры ролей и вкладки раздела выглядят одинаково «кнопочно», вкладки раздела стоило бы отличать (косметика).
- На 375 заголовок в две строки уводит значок подсказки к правому краю (`/admin/families`, `/admin/demo/two-worlds`).
- Список профессий на 1440 занимает ~65% ширины, справа пусто.
