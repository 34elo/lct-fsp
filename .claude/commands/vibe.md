Ты — **диспетчер** одного блока. Задача: реализовать задачи своего блока по плану, пока человек отдыхает. Вопросов не задавай — решай сам по документам. Сам код не пишешь: каждую задачу отдаёшь сабагенту и держишь свой контекст маленьким.

Аргументы: $ARGUMENTS. Первое число — **блок**, второе (необязательное) — лимит задач. Если блок не указан — напиши «Укажи блок: `/vibe 0` (этап 0), `/vibe 1` или `/vibe 2`» и остановись.

| Блок | Ветка | Раздел очереди в `docs/process/plan.md` | Журнал |
|---|---|---|---|
| 0 | `stage0` | `#### 4.2.0` | `### 6.1` |
| 1 | `block1` | `#### 4.2.1` | `### 6.1` |
| 2 | `block2` | `#### 4.2.2` | `### 6.2` |

Правила работы двумя блоками — `docs/process/blocks.md`. Сам прочитай только §0 и §8 этого файла (`sed -n '/^## 0/,/^## 1\./p;/^## 8/,/^## 9/p' docs/process/blocks.md`).

## Старт
1. `git status --porcelain` не пуст → закоммить на текущей ветке: `chore: состояние перед вайбкодингом`.
2. Перейди на ветку блока (`git switch <ветка>`). Её нет → создай от `origin/dev` (`git fetch origin dev` и `git switch -c <ветка> origin/dev`). Работай только в ней.
3. Прочитай **только** свой раздел очереди и таблицу точек стыковки:
   `sed -n '/^#### 4.2.T/,/^#### 4.2.0/p;/^#### 4.2.<N>/,/^#### /p' docs/process/plan.md` (подставь номер раздела).

## Какие задачи брать
- Только из своего раздела. Статус `⏳`, режим 🤖 или 🤝. Режим 👤 пропускай.
- **Зависимости:**
  - ID задачи → статус `✅` или `🔍` в любом разделе плана (свой, чужой, архив v1). Ищи через `grep -n '| <ID> |' docs/process/plan.md`;
  - `Т0`…`Т3` → статус ✅ в таблице §4.2.T. Нет → задачу не брать, она ждёт точку стыковки;
  - `P*` → считай выполненными. Чего нет, заменяй заглушками:
    - нет GPU или модели → `ML_FAKE=true` и OpenAI-совместимый клиент с фейком;
    - нет дизайна → экраны по `docs/design/brief.md` и токенам из `docs/design/brand.md`;
    - нет токенов, домена, API ФСП → код и тесты на моках, настоящие значения через переменные окружения.
- **Блок 2 до Т0:** брать только E19-0…E19-4 и E19-16b.
- Порядок — сверху вниз по своему разделу. Статус `⏸` и `⛔` не брать.

## Цикл (по одной задаче, не параллельно)
1. `BASE=$(git rev-parse HEAD)`.
2. **Сабагент** (general-purpose, `run_in_background: false`, модель из колонки «Модель») с промптом:
   «Репозиторий lct-fsp, ветка <ветка>, **блок <N>**. Сначала прочитай `docs/process/blocks.md` §0 и §8, затем `.claude/commands/task-auto.md` и выполни его для задачи <ID>. Режим: <🤖|🤝>. Предусловия P* считай выполненными: недостающее (GPU, дизайн, токены, API ФСП) заменяй заглушками по AGENTS.md. Меняй только файлы зоны своего блока (blocks.md §3) и общие файлы по правилам §5.»
3. **Проверка** (вывод через `| tail -n 30`):
   - `git status --porcelain` пуст;
   - `git log --oneline $BASE..HEAD` — есть коммиты с ID;
   - команда «Проверка» из отчёта сабагента;
   - `git diff --name-only $BASE..HEAD` — нет файлов чужой зоны (blocks.md §3). Есть → откати эти файлы отдельным коммитом и оформи заявку (blocks.md §9).
4. **Итог задачи:**
   - **ок** → статус `✅ <хеш>` (для 🤝 — `🔍 <хеш>`);
   - **отчёт «БЛОКЕР»** → `⛔ <причина до 10 слов>`. Блокер на стыке → `⛔ стык З-<N>-<NN>` и строка в журнал стыков (blocks.md §13);
   - **проверка упала** → один сабагент-исправитель с последними 40 строками ошибки. Снова плохо → `git stash push -u -m "vibe-failed <ID>"`, `git revert --no-edit $BASE..HEAD`, статус `⛔ <кратко>`.
5. Поменяй **только ячейку «Статус»** этой задачи в своём разделе `docs/process/plan.md` → коммит `chore(plan): <ID> <статус>` → `git push origin <ветка>` (не получилось — продолжай, запушишь в конце).
6. Каждые 5 задач — одна строка прогресса в чат («блок 1: сделано 10, ⛔ 1, дальше E22-3»).

## Остановка
- лимит задач набран;
- подходящих задач нет — напиши «ОЧЕРЕДЬ БЛОКА <N> ПУСТА» или «ЖДЁМ Т<n>», если оставшиеся задачи ждут точку стыковки;
- три задачи подряд упали (скорее всего, сломано окружение);
- закончились лимиты модели.

## В конце
В своей таблице журнала (`plan.md` §6.1 или §6.2) добавь строку:
- дата и ветка;
- сделано (ID);
- ⛔ с причинами, открытые заявки на стык;
- что проверить человеку: 🔍-задачи и странности.

Закоммить и `git push origin <ветка>`. Выведи итог в 10 строк.

## Нельзя
- пушить куда-либо, кроме `origin <ветка своего блока>`; `--force`; слияние в `main` или `dev`; слияние ветки другого блока; `reset --hard`, `clean`;
- менять статусы и журнал чужого раздела;
- чтение `.env`;
- платные внешние сервисы, создание аккаунтов.
